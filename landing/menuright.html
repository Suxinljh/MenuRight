MenuRight

为 macOS 访达（Finder）右键菜单补充一批「本来应该有」的操作。 A batch of “should have been there” actions for the macOS Finder context menu.

复制路径、打开终端、新建文件夹与文档、压缩解压 —— 这些 macOS 本来就能做，只是藏在别处。MenuRight 把它们放回你右键的地方。 Copy a path, open Terminal, create a folder or a document, compress and extract — macOS can already do all of it, it is just buried elsewhere. MenuRight puts it back where you right-click.

核心不变量：Finder 扩展本身没有任何文件写入权限 —— 它只发送请求，所有副作用都由主应用在你已授权的文件夹范围内执行。这一条无法在设置里关闭。 The core invariant: the Finder extension has no file-write access at all — it only sends requests, and every side effect is performed by the main app, inside folders you have authorised. It cannot be turned off in settings.

为什么需要它Why it exists

拿一个路径Grabbing a path

以前：右键 → 按住 Option → 拷贝「…」作为路径名。现在：右键 → 复制路径。 Before: right-click → hold Option → Copy “…” as Pathname. Now: right-click → Copy Path.

在这个文件夹开终端Terminal, here

以前：先开终端，再 cd 过去。现在：右键空白处 → 打开终端。 Before: open Terminal, then cd into the folder. Now: right-click the background → Open Terminal.

新建一个文档A new document

以前：打开 Word / Pages 新建，再另存为到目标文件夹。现在：右键 → 新建文件 → 选类型。 Before: launch Word or Pages, create, then Save As into the folder. Now: right-click → New File → pick a kind.

功能总览What it does

  • 右键菜单The context menu

    选中文件、选中压缩包、文件夹空白处，三种场景各有各的条目；不需要的操作可以在设置里整项关掉。 Three contexts — selected items, an archive, the folder background — each with its own rows. Operations you don’t want can be switched off entirely.

  • 常用项图标Real icons

    常用文件夹、软件、网页在设置列表和右键子菜单里都显示真实图标 —— 文件夹用它自己的图标（包括你在访达里自定义的），软件用 App 图标，网页用站点 favicon。 Favourite folders, apps and websites show their real icons in both the settings list and the submenu — folders use their own icon (including one you customised in Finder), apps use the app icon, websites use the site favicon.

  • 代码预览Code preview

    按空格预览代码文件时用自己的高亮器上色，Markdown 则真正渲染出来；9 套配色、17 种语言，设置里的预览用同一个引擎、同一份配置。 Space-bar previews get syntax colour from our own highlighter, and Markdown is actually rendered. 9 themes, 17 languages — the settings preview uses the same engine and the same config.

  • 压缩与解压Archives

    压缩为 ZIP / TAR / TAR.GZ / TAR.BZ2，或打开自定义压缩对话框；解压同样在右键里完成。 Compress to ZIP / TAR / TAR.GZ / TAR.BZ2, or open the custom compression sheet; extraction lives in the same menu.

  • 新建文件New files

    文本 / Markdown / HTML / CSS / JavaScript / JSON，以及 Word / Excel / PowerPoint（自研 OOXML 生成）和 Pages / Numbers / Keynote。 Text / Markdown / HTML / CSS / JavaScript / JSON, plus Word / Excel / PowerPoint (OOXML generated in-house) and Pages / Numbers / Keynote.

  • 菜单栏与更新Menu bar & updates

    菜单栏常驻图标（打开设置 / 检查更新 / 退出）；关掉设置窗口不会退出主应用，因为扩展每次执行操作都需要它在。 A persistent menu-bar icon (Open Settings / Check for Updates / Quit). Closing the settings window does not quit the app, because the extension needs it alive.

支持的格式Formats

  • ZIP压缩 · 解压Create · Extract

  • TAR.GZ压缩 · 解压Create · Extract
  • TAR.BZ2压缩 · 解压Create · Extract

RAR 完全不做（没有可用的纯 Swift / MIT 许可实现）；7-Zip 与 XZ 只能解压不能创建；加密、分卷、固实压缩一律不支持 —— 自定义压缩对话框里这三项置灰并写明原因。 RAR is not implemented at all (no pure-Swift, MIT-licensed implementation available); 7-Zip and XZ can only be extracted, never created; encryption, split and solid archives are unsupported — the custom compression sheet greys those three out and states why.

安全Safety

  • 解压会拒绝 ../ 等一切试图逃出目标目录的路径。 Extraction rejects ../ and anything else trying to escape the destination directory.
  • 同名文件策略由你决定：保留两者 / 跳过 / 覆盖。 You choose what happens on a name clash: keep both, skip, or overwrite.
  • 压缩时跳过符号链接（避免打包你并未选中的文件），解压时也不会创建符号链接。 Symlinks are skipped when compressing (so you never package files you did not select) and never created when extracting.
  • 解压默认有体积上限，防止「压缩炸弹」；压缩包在内存里组装、最后才落盘，所以取消不会留下半个文件。 A size ceiling guards against archive bombs; the archive is assembled in memory and only written at the end, so cancelling never leaves half a file.

权限与隐私Permissions & privacy

扩展不写文件，主应用才写The extension never writes

Finder 扩展是一个沙箱进程，只负责在菜单里显示条目并发送请求；所有真正的文件操作都在主应用里执行。所以「右键菜单里点了没反应」通常意味着主应用没在运行 —— 菜单栏图标就是为此常驻的。 The Finder extension is a sandboxed process that only shows menu rows and sends requests; every real file operation runs in the main app. That is why “the menu item did nothing” usually means the main app is not running — which is exactly why the menu-bar icon stays there.

未授权的路径写不进去Unauthorised paths cannot be written

所有写操作都要求目标路径位于你已授权的文件夹内。未授权的路径无法写入 —— 这是 macOS 沙箱的限制，不是 bug。移动硬盘、网络卷在授权后同样可用。 Every write requires the target to sit inside a folder you authorised. An unauthorised path simply cannot be written — that is the macOS sandbox, not a bug. External drives and network volumes work once authorised.

不收集数据No data collection

没有账号、没有遥测、没有云同步，设置与授权记录只存在这台设备上。唯一需要的系统级权限是启用 Finder 扩展 —— 不用辅助功能、不用 AppleScript、不用 CGEvent。 No account, no telemetry, no cloud sync; settings and authorisations live only on this machine. The only system-level permission required is enabling the Finder extension — no Accessibility, no AppleScript, no CGEvent.

只有两个网络行为Exactly two network behaviours

一是检查更新（读 GitHub Releases，默认开启、每天最多一次）；二是你添加「常用网页」时抓取站点 favicon。扩展进程没有任何网络权限，抓取只发生在主应用里。 One is the update check (reads GitHub Releases, on by default, at most once a day); the other is fetching a site favicon when you add a favourite website. The extension process has no network access at all — that fetch happens in the main app.

安装与使用Install & use

  1. 01

    下载对应架构的安装包（Apple Silicon 或 Intel；DMG 或 ZIP 任选），打开后把 MenuRight.app 拖进「应用程序」。 Download the build for your architecture (Apple Silicon or Intel; DMG or ZIP), then drag MenuRight.app into Applications.

  2. 02

    首次打开若系统提示无法验证开发者，请在「访达」里右键应用 →「打开」。本项目未做公证，属于预期行为。 If macOS warns that the developer cannot be verified on first launch, right-click the app in Finder → Open. The build is not notarised; this is expected.

  3. 03

    在首次使用引导里点「打开系统设置…」，于「隐私与安全性 → 扩展 → 已添加的扩展」中启用 MenuRight 扩展。这是本应用唯一需要的系统权限。 In the first-run guide, click Open System Settings… and enable the MenuRight extension under Privacy & Security → Extensions → Added Extensions. It is the only system permission this app needs.

  4. 04

    打开「文件夹权限」，授权你希望 MenuRight 操作的文件夹（可批量添加）。未授权的路径无法写入。 Open Folder Permissions and authorise the folders you want MenuRight to work in (you can add them in bulk). Unauthorised paths cannot be written.

  5. 05

    回到访达，在文件或文件夹上点右键即可看到菜单。 Back in Finder, right-click a file or folder and the menu is there.

常见问题FAQ

右键菜单里什么都没有？ The menu does not appear at all?

先确认 Finder 扩展已启用：系统设置 → 隐私与安全性 → 扩展 → 已添加的扩展。扩展未启用时，设置里会显示红色状态与原因。另外请确认主应用正在运行 —— 菜单栏图标是它的出口。 First check that the Finder extension is enabled: System Settings → Privacy & Security → Extensions → Added Extensions. When it is off, the app shows a red status and the reason. Also make sure the main app is running — the menu-bar icon is its home.

提示「无法验证开发者」，打不开？ “Developer cannot be verified” — it will not open?

本项目没有做公证（notarization），这是预期行为。在「访达」里右键应用 →「打开」即可。若在别的 Mac 上因预置描述文件受限而无法启动，请从源码构建。 The build is not notarised, so this is expected. Right-click the app in Finder → Open. If a provisioning-profile restriction stops it on another Mac, build from source instead.

为什么某个文件夹里操作失败了？ Why did an operation fail in a certain folder?

那个路径还没有被授权。打开「文件夹权限」把目标文件夹加进去即可（可批量添加）。这是 macOS 沙箱的限制，不是 bug。 That path has not been authorised yet. Open Folder Permissions and add the folder (bulk adding works). This is the macOS sandbox, not a bug.

为什么不支持 RAR / 加密压缩 / 分卷？ Why no RAR, encryption or split archives?

RAR 没有可用的纯 Swift、MIT 许可实现；加密与分卷需要自研 ZIP 加密或 7-Zip 写入能力，本版本没有。7-Zip 与 XZ 只能解压不能创建。这些都会在界面里写明原因，而不是静默失败。 There is no pure-Swift, MIT-licensed RAR implementation; encryption and split archives would need in-house ZIP encryption or 7-Zip writing, which this version does not have. 7-Zip and XZ can only be extracted. The UI states the reason rather than failing silently.

TypeScript（.ts）为什么不管？ Why does it ignore TypeScript (.ts)?

系统把 .ts 解析成 public.mpeg-2-transport-stream（MPEG-2 传输流），声明它会把视频文件抢过来。同理 .rs、.go、.sql 没有稳定 UTI，也不接管。 macOS resolves .ts to public.mpeg-2-transport-stream (MPEG-2 transport stream), so claiming it would hijack video files. Likewise .rs, .go and .sql have no stable UTI and are left alone.

关掉设置窗口后，为什么主应用还在？ Why is the app still running after I close the window?

Finder 扩展由访达按需拉起、用完自己退出，没有 App 能启动或阻止它退出；它每次执行操作都要把活交给主应用。所以关闭窗口不再退出主应用，菜单栏的「退出」是唯一的出口（⌘Q）。 Finder launches the extension on demand and lets it exit on its own — no app can start it or keep it alive — and every operation it performs is handed to the main app. So closing the window no longer quits it; Quit in the menu bar (⌘Q) is the only exit.

会自动更新吗？ Does it update itself?

不会自动下载或替换 App。检查更新只做三件事：检查 → 提示 → 打开下载页。默认开启、每天最多一次；手动「立即检查」不受限制，且每种结果都会明确告诉你（包括失败原因）。 It never downloads or replaces the app by itself. The update check does three things only: check → prompt → open the download page. It is on by default, at most once a day; a manual check is unlimited and always reports its outcome, including the reason for a failure.
