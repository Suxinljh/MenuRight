## 失败话术:三个问题不能合成一句话

`UpdateCheckError` 原来只有 `httpStatus(Int)` / `transport(String)`,于是
"配额用尽(服务端拒答)" 和 "根本连不上(请求没出去)" 都被渲染成
`检查更新失败:HTTP 403` —— 用户看不出该等一小时还是该查路由器。

- 新分类:`rateLimited(resetAt: Date?)` / `offline` / `timedOut` / `httpStatus(Int)` / `transport(String)`。
- `requestLatestRelease()`:`403` **和** `429` 走限流分支,恢复时间先读 `Retry-After`(秒),
  再读 `X-RateLimit-Reset`(epoch),都没有就退回不带时间的文案。
  `URLSession` 抛的 `URLError` 按 code 分流:notConnectedToInternet / networkConnectionLost /
  cannotConnectToHost / cannotFindHost / dnsLookupFailed / dataNotAllowed / internationalRoamingOff
  → `offline`;`timedOut` → `timedOut`;其余保留 `transport(localizedDescription)`。
- 新增 `UpdateFailureMessage.make(for:language:)`:纯函数,失败话术的**唯一出口**。
  设置面板那一行(`UpdateChecker.message(for:)`)与菜单栏弹框(`StatusMenuUpdateOutcome`)
  都经过它,不会各说各话。限流文案会带本地时间,例如「约 17:00 之后可重试」。
- 新文案 4 条:`generalUpdateOffline` / `generalUpdateTimedOut` / `generalUpdateRateLimited` /
  `generalUpdateRateLimitedUntil`(带 `%@`)。

## 测试:纯函数不够,补了 3 个端到端

- 5 个纯函数测试:限流 ≠ 断网(两边互相检查不含对方措辞、且不含 `HTTP 403`)、
  限流带上本地时间且占位符被填、连接失败与超时措辞不同、404(尚无 Release)保持原话术、
  `rateLimitReset` 的优先级(Retry-After > X-RateLimit-Reset > nil,包括 "not a number")。
- **3 个 URLProtocol 端到端测试**:真的走 `checkNow()` 一遍,断言最终 `state.failed(message)`。
  必要性:把 403 归到 `rateLimited` 的那个 `switch` 是 `private` 的,纯函数测试不会因为
  有人把它改回 `default` 而失败。实现为**每个行为一个 URLProtocol 子类、零静态可变状态**
  (共享 static "该返回什么" 的写法在 XCTest 并行时会互相打架)。
- **坑**:第一版断言写死中文,测试里 `SettingsStore` 默认语言是 `.system` → 本机解析成英文,
  三条全挂(日志里能看到英文句子其实是对的)。改成在 scratch store 里显式 `language = .simplifiedChinese`;
  这类断言不能依赖跑测试那台机器的语言。
- `UpdateChecker.rateLimitReset(in:now:)` 写成 `nonisolated static`,测试才能直接构造
  `HTTPURLResponse` 断言(该类是 `@MainActor`)。
