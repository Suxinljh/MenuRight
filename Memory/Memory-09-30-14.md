## 实现

1. `Shared/Settings/OnboardingFlow.swift`(可单测):`OnboardingStep`(enableExtension →
   authorizeFolders → ready)+ `OnboardingFlow` 状态机 + `shouldPresent(hasCompleted:isExtensionEnabled:)`。
   判断规则:**没完成过引导,或扩展处于关闭状态**就出现 —— 扩展关着应用等于不可用,
   该把两个必做步骤摆到用户面前;"稍后再说"只跳过本次启动(下次扩展仍关着会再出现)。
2. `MenuRight/App/Settings/OnboardingView.swift`:固定宽度 520 的 sheet,三步各自的内容 + 页脚
   (稍后再说 / 上一步 / 下一步 / 开始使用)。第 1 步用 `FIFinderSyncController.isExtensionEnabled`
   取实时状态、`showExtensionManagementInterface()` 打开系统界面(**官方 API,不猜深链**)。
   第 3 步汇总状态 + 复用工具栏的「重启 MenuRight」+ 说明"设置改动不需要重启"。
3. `MenuRight/App/FolderAuthorizationAction.swift`:把 NSOpenPanel + 安全作用域书签 + 落库
   抽成共享动作,`FolderAccessView` 与引导第 2 步走**同一条**代码路径(各自负责报错 UI),
   避免"引导里授权出来的东西不一样"。`FolderAccessView.displayName` 一并移入。
4. `SettingsRootView`:`.sheet` + `@AppStorage("hasCompletedOnboarding")`;
   复核钩子 `MENURIGHT_ONBOARDING=enable|authorize|ready`。
5. `SettingsGroup.title` 改为可选(引导卡片不需要小标题)。
6. pbxproj 新增 4 个文件(引导模型进 app+测试;视图与授权动作进 app),用"先查重再取 ID"的方式命名。

## 版式/状态踩坑(都由截图发现,不是推断)

1. **`@State(initialValue:)` 冻结父级值**:`OnboardingView` 原本用 `initialStep` 初始化内部
   `@State flow`,导致复核钩子 `MENURIGHT_ONBOARDING=ready` 拍出来仍是第 1 步 ——
   State 只认第一次构造时的值。改为 `@Binding var step`,由 `SettingsRootView` 持有。
   **教训:凡是"父级稍后才设置"的初值,都不要用 `@State(initialValue:)`。**
2. **固定高度 sheet 把余高分给 `Text`**:每个段落下方出现 60pt 左右的空隙(标题→正文、
   正文→卡片都被撑开)。显式 `Spacer()` 不够,最终用
   `.fixedSize(horizontal: false, vertical: true)` 让步骤内容按理想高度排布。
   判断依据是逐屏截图里量出的间距,而不是"看着差不多"。
