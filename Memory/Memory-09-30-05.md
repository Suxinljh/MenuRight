## 关键技术结论

1. **必须钉 tag**:Lucide 会重命名图标(前一轮 `file-plus-2`/`folder-star` 已 404),
   而 tag 形式**不带 v**(`1.49.0` 有、`v1.49.0` 无)。用户给的 9 个名字在 1.49.0 下全部 200,
   但 `file-plus-corner` 在 `main` 上取不到 —— 再次说明不能依赖 main。
2. **模板渲染 = 只需 alpha**:因此 SVG 里的描边颜色无所谓(`currentColor` 实测与 `#000000`
   光栅化像素完全一致),dark mode 与选中态(白色)都由系统着色,不需要第二套素材。
3. **只删根标签的尺寸属性** —— 见下方踩坑。
4. Xcode 支持 SVG 进 asset catalog:实测 actool 无警告,且能产出真正的 Vector rendition;
   根标签的 `width/height` 去掉、只留 `viewBox`,就能跟着 16pt frame 缩放。

## 踩坑(这次最有价值的一条)

**文件级正则删 `width/height` 会把子元素尺寸一起删掉。** 第一版规范化脚本用
`re.sub(r'\s(width|height)="\d+"', "", text)`,结果 `app-window-mac` 的窗口主体
`<rect width="20" height="16" x="2" y="4" rx="2"/>` 变成 `<rect x="2" y="4" rx="2"/>`,
渲染出来只剩三个点(三个 traffic light path)。9 个图标里只有它中招。

- **编译期、actool、单测都发现不了**(资源存在、名字正确、能编译);
  **是靠截图看出来的**。教训:换图标/换图标集之后必须截图逐个核对,不能只信构建通过。
- 修复:只对根标签做替换(`re.match(r"\s*<svg\b[^>]*>")` 之后只改这一段),
  并加断言:**除根标签与 `currentColor` 替换外,body 必须逐字节相同**,否则脚本报错退出。
  这个断言自身也踩了个小坑(用清理前的根标签长度去切片比较),已修。
- 另外用一次独立审计复核:把 9 个生成文件与上游 raw 文件逐字节比对 body,全部 identical。
