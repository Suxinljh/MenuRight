本轮:**Markdown 预览从"源码高亮"改成"真正的渲染"**。起因是用户反馈:装了 MenuRight 之后,
`.md` 原本由 WPS Office 的快速查看扩展渲染,现在被 MenuRight 顶替成了纯文本高亮。

```
Automated: PASS  (xcodebuild test:548 tests / 0 failures / 1 skipped)
Manual:    PENDING(渲染观感,验证手册 §3.10 第 69–71 项)
```

## 先回答的问题:"能不能按语言做勾选开关"

**不能**,两条硬约束:

1. `QLSupportedContentTypes` 写死在**签名后的 Info.plist** 里,运行时没有任何 API 能改;
2. Quick Look **没有"我不接管,交给下一个"的机制**。

第 2 条是**实测**出来的,不是猜的:

| 场景 | 结果 |
| --- | --- |
| 对照组:禁用 MenuRight 的 QL 扩展后预览 `.md` | `WPSQuickLook.appex` 进程被拉起,markdown 正常渲染 |
| 实验组:在 `preparePreviewOfFile` 里对 `.md` 抛错 | 我们的进程起来了,但**没有任何渲染**,`WPSQuickLook` **也没有**被拉起(面板空掉) |

顺带纠正:顶替 markdown 的**不是 Typora**,而是 **WPS Office** 的快速查看扩展
(`/Applications/wpsoffice.app/Contents/PlugIns/WPSQuickLook.appex`),它声明了
`net.daringfireball.markdown` 以及 `com.typora.markdown` / `io.typora.markdown`。

用户拍板:**不做开关,MenuRight 自己把 Markdown 渲染出来**。

## 实现

- `Shared/CodePreview/MarkdownDocument.swift`(新):`MarkdownDocument` 块模型 + `MarkdownAnalyzer`。
  解析交给 Foundation 的 `AttributedString(markdown:options: .full)`,再把 run 的
  `presentationIntent` 归成块:标题/段落/列表(深度+序号或 •)/引用/围栏代码块(带语言提示)/
  表格(表头+数据行)/分隔线;inline 侧取 `inlinePresentationIntent` 的
  `.stronglyEmphasized`/`.emphasized`/`.code` 与 `run.link`。
  表格对齐放在模型里(`alignedLines`),**中日韩字符按两列宽**计算,两个渲染端才不会各算各的。
- `Shared/CodePreview/CodePreviewMarkdownBuilder.swift`(新):AppKit 渲染。正文用**系统字体**
  (等宽字体读长段落很难受),行内代码/代码块/表格用设置里的等宽字体;代码块**复用 `CodeHighlighter`**
  (按 fence 的语言提示选语言);颜色全部取自主题(标题/正文=foreground、行内代码=string、
  链接=function+下划线、引用=comment、列表标记=keyword、代码块=各自 token 色、表格表头=keyword)。
- `CodePreviewDocumentBuilder.makeDocument` 现在**分派**:`.markdown` 走渲染,其余走高亮
  (原来的实现拆成 `makeHighlightedDocument(source:language:...)`)。
- 设置面板(`CodeThemeSettingsView`)的示例预览同样切到渲染:`.markdown` 时用 SwiftUI 走同一份块模型
  (bold/italic 用 `Font`,不依赖 `inlinePresentationIntent` —— `Text` 对它支持不稳定)。
- `CodePreviewSamples` 的 markdown 示例改成能展示渲染效果的文档(标题/列表/引用/围栏代码/表格)。
- `Info.plist`:`net.daringfireball.markdown` **加回** `QLSupportedContentTypes`(注释写明"接管就必须渲染")。
- 单测:`MenuRightTests/CodeMarkdownTests.swift`(19 例):块分析、表格对齐与中文宽度、
  渲染而不是高亮、标题字号、粗体、链接色+下划线、行内代码等宽、代码块真的调用了高亮器、截断。

## 踩坑

1. **`NSTextBlock` 的背景在普通 `NSTextView` 里不画**:代码块底色 7% 与 16% 渲染出的 PNG
   **字节完全相同**(sha256 一致)→ 改成给每个 run 上 `.backgroundColor`(整行含换行也带上),
   底色才可见。这个只有把渲染结果导成 PNG 看才发现。
2. `NSMutableParagraphStyle` 没有 `paragraphSpacingAfter`,是 `paragraphSpacing`;
   `NSTextBlock` 的 Swift 名字是 `setWidth(_:type:for:)`,没有 `forLayer:`/`edge:`。
3. `InlinePresentationIntent` 的成员是 `.stronglyEmphasized` / `.emphasized`(不是 `.strong`/`.emphasis`)。
4. 单测里用 `"a"` 去查表格数据格的颜色会命中表头 `"Name"` 里的 `a` —— 断言子串必须唯一。
5. 构建时撞到一次 DerivedData 的 module cache 被清(`SDKStatCaches... not found`),
   重跑即恢复;和安装脚本头部记录的"Xcode 与 xcodebuild 共用 DerivedData"是同一类环境问题。
