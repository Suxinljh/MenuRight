## 做了什么

1. **三个压缩模式真的不一样了**(以前 fast/standard/maximum 对 `.tar.gz` 完全没有作用):
   zip / 7z / tar.gz 用压缩等级 1/6/9;bzip2 用块大小 1/5/9 ×100KB;**tar 本身不压缩,模式对它无效**(对话框里明写)。
   关键:`Shared/Archive/GzipWriter.swift`(新)自己用 zlib 拼 gzip —— SWCompression 的 `GzipArchive.archive(data:…)`
   内部 deflate 只有「stored vs 静态 Huffman」两种,等级根本传不进去,所以 `.tar.gz` 以前永远一个大小。
2. **分卷压缩**:`Shared/Archive/ArchiveVolumeSet.swift`(新)。写:`write(_:baseURL:volumeBytes:overwrite:)` 切片成
   `name.ext.001/.002…`(最多 999),重写时先 `removeStaleParts` 清尾巴。读:`resolve(_:)` 把多片拼进
   `temporaryDirectory/MenuRight-Volumes/<UUID>/` 的 scratch 文件,`discard()` 清理;`ArchiveExtractor.extract` 与
   `ArchivePasswordResolver.resolve` 入口都先 resolve;「解压后删除压缩包」改成删**全部分片**。档位 10/50/100/250/700 MB。
3. **固实压缩(仅 7z)**:`SevenZipWriter.archive(entries:mode:password:solid:encryptsFileNames:control:onEntry:)` 透传
   `setShouldCreateSolidArchive(_:)`(库默认 true)。
4. **7z AES-256 读写**:写用 `setPassword` + `setShouldEncryptContent(true)`,勾「加密文件名」再加 `setShouldEncryptHeader(true)`。
   读用新文件 `Shared/Archive/SevenZipPasswordSource.swift`:`SevenZipEncryption.needsPassword/validates` +
   `SevenZipPasswordMemberSource`(先用 `OutStream` 试解最小的加密项验证密码,再整包 `extract(to:)` 到 scratch 目录取文件 ——
   7z 默认固实,逐项解码会重复解整块)。SWCompression 对加密 7z 直接抛 `SevenZipError.encryptionNotSupported`,所以加密路径全走 PLzmaSDK。
   **已知取舍**:加密 7z 解压时符号链接不落盘(PLzmaSDK 没有符号链接 API),`members()` 也不报目录项。
5. **顺手修掉一个会让 7z/tar 全废的回归**:`FileOperationDispatcher.swift:569` 对每个归档都无条件调 resolver,而 resolver 内部直接
   `try ZipReader(fileURL:)` —— 非 ZIP 一律抛 `notAnArchive`,于是经 Finder 菜单解压 7z/tar/tar.gz 全报「Not a readable archive」。
   现在 resolver 先 `ArchiveFormats.detect`:zip → ZIP 探测、7z → 7z 探测、其余 → `.notNeeded`。
   (老测试没抓到,是因为那批用例清一色用 `RawZipBuilder` 造 zip 夹具。)
6. UI(`CustomCompressionSheet.swift`):ZIP 与 7Z 时「加密压缩」「分卷压缩」可用(7Z 另有「加密文件名（仅 7z）」与「固实压缩」),
   TAR 系置灰并写明原因;删掉 `.archiveOptionUnsupported` / `.archiveUnsupportedOptionsNote`,换成 9 条说明文案(模式差别、
   分卷命名、7z 加密说明)。

## 坑(下次别踩)

- `ArchiveFormat` 是 String 枚举且 `case sevenZip` **没有显式 rawValue** ⇒ rawValue 是 `"sevenZip"`;`"7z"` 只是扩展名
  (`fileNameExtension(for:)`)。自测 env 里写 `7z` 会得到 `archive_unsupported`。
- 7z 的**头在文件末尾**,加密文件名时整个头也加密 ⇒ 对 `.001` 单片判断 `needsPassword` 一定是 false,必须先
  `ArchiveVolumeSet.resolve` 拼回整包(自测里一开始 `confirmEncrypted=false` 就是这个)。
- 沙箱里 `createDirectory` 也要 security-scoped access;自测回读步骤把「建目录 + 解压 + 判断加密」全塞进
  `FolderAuthorizationAccess.withAccesses(to:folders:)`,否则 `NSCocoaErrorDomain Code=513 … Operation not permitted`。
- `let outcome: String` 在 `do` 里初始化之后又插入了会 throw 的语句 ⇒ `error: immutable value 'outcome' may only be
  initialized once`;拆成两个 do/catch(写法见 `MenuRightApp.swift` 自测段)。
- 测试断言要注意:`ArchiveExtractor.write` 会把 `source.contents` 抛出的 `ArchiveError` 变成 `.failed(describe(error))`
  而**不抛出** ⇒ 加密包没密码/密码错时看到的是 `summary.failed == 1`,不是 throw;`ArchiveExtractionSummary` 字段是
  `written/skipped/failed`(没有 `extracted`)。
