## A. 解压/压缩的修复

侦察发现的短板(读代码得出,非猜测)与修法:

| 问题 | 修法 |
| --- | --- |
| `ArchiveSettings.destination` / `customDestinationPath` **运行时没有任何代码读取**,设置面板是装饰品 | 新增 `FinderArchives.Destination`(ask / folder / duplicatesFirstItem),扩展据此构建「解压 ▸」第二项;主 App 侧沿用已有的 `destinationDirectory` 参数 |
| 「允许的压缩格式」只过滤解压菜单 | `FinderArchives.enabledCompressionFormats()` 过滤 `压缩 ▸`;主 App 在 `handleCompressItems` 复检(customize 路径豁免);自定义压缩对话框的格式下拉同样跟随 |
| 自定义压缩的「取消」只关对话框 | `CompressionCancellation`(@unchecked Sendable + NSLock)+ `ArchiveCompressor.compress(isCancelled:)`,遍历每个条目轮询;新增 `ArchiveError.cancelled` |
| `deletesArchiveAfterExtraction` 在「全部条目被跳过」时仍删原包 | 只有 `failed == 0` **且没有任何内容级跳过**(元数据跳过不算)才删 |
| 读不到源文件时静默写入 0 字节条目 | 改为 `ArchiveError.readFailed("「name」could not be read: …")`,整个压缩失败 |

**用户拍板的语义(重要,别再改回去)**:「解压位置」**只作用于「解压到指定位置…」这一项**。
- 每次询问(默认)→ 面板
- 指定文件夹 → 该项标题变成 `解压到「<文件夹名>」`(`.finderMenuExtractToFolder` + `String(format:)`),直接解压过去
- 压缩包所在文件夹 → 与第一项重复,该项隐藏
- **「解压到当前文件夹」永远是字面行为**(压缩包所在文件夹),不受设置影响

选这套而不是「设置决定主解压项落点」,是因为后者要把默认值从 askEachTime 改成 sameFolder 并做一次性迁移,否则现有用户升级后行为会变。用户明确选了前者。

标题回放仍是唯一键:Finder 丢掉 `representedObject`,所以 `performExtractArchives` 用「点击标题 + **实时读取的设置**」重新推导,再比对期望标题;设置中途变更导致标题对不上时**回退到弹面板**(宁可多问一次,不可解压到错的地方)。

## B. 常用项图标(设置列表 + Finder 子菜单)

- 模型:三个 `Favorite*` 结构 + `FinderFavoriteEntry` 新增 `iconFile: String?`(**不属于 `identityKey`**,它是缓存键不是身份)。
- 生产者只有主 App:`MenuRight/App/FavoriteIconProvider.swift`(新文件,**已手改 pbxproj 注册进 app + tests 两个 target**,ID:`AAFAVICON1` / `ABFAVAPP01` / `ABFAVTST01`)。渲染 64×64 PNG → `<App Group>/FavoritesIcons/<kind>-<uuid>.png` → 文件名回写进设置载荷。
- 消费者只有扩展:`FinderFavoriteIcons.image(named:in:)` 按文件名读回并设成 `NSMenuItem.image`(`FinderSync.addItem` 新增 `image:` 参数,只有常用项传图)。跨进程传递的**只有文件名**,不传路径。
- favicon:主 App 抓 `https://<host>/favicon.ico`,失败再解析页面 `<link rel="…icon…">`(`FaviconLoader`,纯逻辑有单测);因此主 App entitlements 新增 `com.apple.security.network.client`。**扩展依然没有网络权限**。抓不到就纯文字。
- 补齐时机:`FavoriteIconBootstrap.run(store:)` 在 `applicationDidFinishLaunching` 调用,否则装完不打开设置页就没有图标;三个设置面板的「刷新」按钮走 `force: true`。
- 删除收藏项时一并删 PNG,避免容器里留孤儿文件。

**推翻了 2026-09-30 的决定**:上一版是 **template 图片**,Finder 绘制扩展菜单图片时不做高亮/禁用染色,选中行显示黑图标,于是把菜单图标整个撤了。全彩 PNG 没有染色这一步,不受该限制。**图标列内边距的代价仍然存在**——这是用户已知并接受的前提(选项里写明了)。README 新增「常用项图标」一节,`MenuRightSettings.iconAsset`、`FinderMenuBuilder`、`check-icons.sh` 里三处「菜单不放图标」的注释/说明已同步改写,避免与实现矛盾。
