## 暂停失效的根因(确定的)

控制消息**确实**走了独立连接,但它被派发到 `ipcQueue` —— 而 `ipcQueue` 是**串行**队列,
文件操作整个生命周期都占着它(卡在 `sendFileOperation` 等答复)。于是:

```
ipcQueue: [压缩操作───────────────(卡住等答复)───────────────] [暂停消息]  ← 压缩结束才发出
controlQueue: [暂停消息]                                                  ← 修复后
```

按了暂停毫无反应,正是用户报的现象。修法:控制消息一律走独立的 `controlQueue`。

**教训**:上一轮我在注释里写了"走独立连接是刻意的",却漏了一层——**连接独立 ≠ 队列独立**。
派发队列同样是共享资源,判断"会不会被挡住"必须一路看到真正执行它的队列。

守卫:`testControlMessagesAreNotQueuedBehindTheOperationTheyInterrupt`(源码级,
抽 `sendControl` 函数体、剥注释后断言不含 `ipcQueue` 且含 `controlQueue`)。
**已实测**:把 `controlQueue` 换回 `ipcQueue` → 该测试失败(exit 65)。
