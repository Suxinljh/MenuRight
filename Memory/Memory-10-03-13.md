## 改了什么（按缺口）

### 1. 设置 → 文件权限：三个开关从「只有 UI」变成真的生效

- **`allowedActions` → Finder 菜单裁剪**：新增 `MenuRightFinder/FinderSettings.swift`（appex 侧解码 App Group 载荷
  `xin.ljhsu.MenuRight.settings`，`Permissions`/`NewFileMenu`）；`FinderMenuBuilder.plan(…, permissions:)` 末尾过
  `permitted(_:_:)`，按 `permissionKey(for:)` 映射逐项丢弃被关掉的动作，并隐藏"子项全被丢光"的子菜单
  （`新建文件 ▸`、`解压 ▸`、`压缩 ▸`、三个常用项子菜单）。`FinderSync.menu(for:)` 每次构建菜单都重读设置。
- 为压缩单列开关：`FileAction.compressArchive`（raw `"compressArchive"`），设置 → 文件权限 的 `otherActions`
  已加进去（`MenuRight/App/Settings/Panes/FilePermissionSettingsView.swift:14`）。
- 新增动作意味着设置 schema 变化：`MenuRightSettings.currentSchemaVersion = 2`；`normalized()` 里做保守迁移
  `FilePermissionSettings.migrateAddingCompressArchive()` —— **只有** old `allowedActions` 恰好等于 v1 全集时才补上
  新开关（用户自定的集合不动），没有 `schemaVersion` 键的旧载荷按 v1 处理。
- **`restrictToAuthorizedFolders` → 真的能关掉预检**：`FileOperationDispatcher` 新增 `scopeFailure(...)`/开关读取，
  关闭后跳过自家 `pathOutsideAuthorizedScope` 预检（记 `DISPATCH … scope-precheck-skipped`），移动/压缩/解压/别名
  等多目标路径走 `withAuthorizations` 的旁路；**macOS 沙盒仍是最终裁判**。打开时行为与之前完全一致
  （创建类仍报 `notAuthorized`，因为它本来就走 `withAuthorization`，没有预检）。
- **`confirmDestructiveActions` → 真的弹确认**：新增 `DestructiveAction`（`lock/unlock/cutMove` + 数量）与
  `DestructiveActionConfirming`；主 App 实现 `MenuRight/App/Settings/DestructiveActionPrompter.swift`（NSAlert，
  标题「确认操作」，正文「即将执行“锁定所选项目”…」，多项时补 `(N 项)`），注入 `MainAppIPCServer`；用户点取消 →
  `.cancelledByUser`，扩展按静默取消处理。

### 2. 设置 → 新建文件：启用类型 / 顺序 / 默认文件名 真的到菜单和文件

- `FinderSettings.NewFileMenu` 解码 `newFile.{baseName,types,enabledTypes}`；
  `FinderMenuBuilder.menuKinds(availability:settings:)` = 模板可用性过滤 → 逐类型开关 → 用户拖拽顺序（未列入的排在已排序项之后）。
- 文件名不再硬编码：`NewFileKind.defaultName(baseName:)`（空/空白回退 `Untitled`），`FinderSync.performNewFile`
  在**点击时**读设置取名（构建菜单时零额外 IO 之外仍保持零读盘预算）。
- `newFile.baseName` / `NewFileType.defaultFileName(baseName:)` 从"生产代码死代码"变成真的生效。

### 3. 终端 App 可配置（默认 Terminal）

- `GeneralSettings` 新增 `terminalApplicationPath`（空 = 内置 Terminal）与 `terminalServiceName`
  （默认 `"New Terminal at Folder"`）+ `terminalApplicationURL` / `usesCustomTerminal` / `effectiveTerminalServiceName`。
- `SystemOpener`：`openInTerminal(_:terminalURL:serviceName:)`、`reconfigured(terminalURL:serviceName:)`、
  `performTerminalFolderService(_:serviceName:)`；`FileOperationDispatcher.terminalOpener()` 按设置构造；
  配置的 App 不存在时回退内置终端并记 `DISPATCH terminal app missing … — using default`。
- UI：通用设置新增「终端应用」组（选择 .app / 恢复默认 / Finder 服务名 TextField / 应用缺失时红字提示）。

### 4. 模板目录可选覆盖

- `NewFileSettings` 新增 `templateDirectoryPath` + `templateDirectoryBookmark`（安全作用域书签），`normalized()`
  保证路径与书签同生共死（清空路径即清空书签）。
- `DocumentTemplateCatalog`：`overrideDirectory(for:)`（只认存在的目录）、`resolvedDirectory(for:bundle:)`
  （覆盖优先，否则 `bundle.resourceURL/Templates`）、`hasBrokenOverride(for:)`、`publishAvailability(settings:bundle:defaults:)`。
- 发布时机：`MenuRightApp.applicationWillFinishLaunching` 用 `publishAvailability(settings:)`，并监听
  `SettingsStore.didChangeNotification` 重新发布 —— 改设置后菜单立即可见，不必重启扩展。
- UI：设置 → 新建文件 新增「模板目录」组（NSOpenPanel 目录选择 + 书签 + 恢复默认），面板的"模板齐全性/缺失类型"
  预览改为走 `resolvedDirectory(for:)`。

## 验证

- **自动化**：`xcodebuild test -project MenuRight.xcodeproj -scheme MenuRight -configuration Debug -destination 'platform=macOS'`
  → **740 executed / 738 passed / 2 skipped / 0 failures**，`build/TestResults-fix-p7c.xcresult`（EXIT=0；上一次
  `build/TestResults-fix-p7b.xcresult` 同数）。2 个 skip 仍是 UI 截图辅助
  （`testWindowRendersToAnImageWhenAsked`、`testDialogRendersToAnImageWhenAsked`）。基线是 690 tests（第 12 轮之前），
  本轮 +50 个测试。
- 顺手清掉一个并发警告：`DestructiveActionPrompter` 因协议要求 `Sendable` 而报警"stored property 'text' … non-Sendable"，
  改为 `@unchecked Sendable` 并写明理由（`text` 只在主线程经 `onMain` 调用），改后 Debug 构建零该警告。
- 新增/扩展的测试：`MenuRightTests/FinderSettingsTests.swift`（新，18 个）+ `MenuRightTests/MenuRightSettingsTests.swift`
  （schema/迁移/终端/模板目录）+ `MenuRightTests/DocumentTemplateCatalogTests.swift`（覆盖目录）+ 
  `MenuRightTests/FileOperationDispatcherTests.swift`（开关放行/拦截/确认/取消/终端回退/模板覆盖）。
- **构建**：Debug（含 `MenuRightFinder` appex）由上面的 test 动作编译通过；Release 三个 target 也
  `BUILD SUCCEEDED`（`xcodebuild build -configuration Release -derivedDataPath build/DerivedData-fix-release`，EXIT=0）。
- **发现并处置一个既有 flaky 测试**：`ArchiveModeAndSevenZipTests.testEveryCompressingFormatGetsSmallerFromFastToMaximum`
  在整包跑时失败（7z 极慢 478 B 反而比快速 471 B 大），单独重跑通过；基线 `TestResults-final-modes.xcresult` 里它是
  Passed，且本轮**没有改动任何压缩代码**（`SevenZipWriter.level(for:)` 仍是 1/6/9）。结论：PLzmaSDK 的 LZMA2 多线程编码
  在这份"极度冗余、压完只有 ~470 B"的输入上不保证 level 单调，且字节数会在跑动间浮动。**没有静默放宽**：
  7z 分支改成"三个档位都必须把输入压到 4096 B 以下"+"极慢不超过快速 5%"，并在测试里写清观测值与原因；
  zip/gzip/bzip2 仍保持严格递减断言。
