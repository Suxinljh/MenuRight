## 关键突破:用 Figma Dev Mode MCP 读设计稿

- `web_fetch` 打不开 `www.figma.com`(本机解析到非公网地址,被环境拦;`web_search` 仍是 401)。
- 用户提供了本地 MCP:`http://127.0.0.1:3845/mcp`(Figma Dev Mode MCP Server 1.0.0,
  protocol 2025-06-18)。**这是本机读 Figma 的唯一通路。**
- 协议要点(已写成可复用工具 `Scripts/figma-mcp.py`):
  1. `POST /mcp` + `Content-Type: application/json` + `Accept: application/json, text/event-stream`;
  2. `initialize` → 响应头 `mcp-session-id` **必须**在后续请求里带上(否则失败);
  3. 再发 `notifications/initialized`(无 id);
  4. 之后 `tools/list` / `tools/call`。响应是 SSE(`data: {...}` 单行 JSON)。
- 可用工具:`get_design_context`、`get_screenshot`、`get_metadata`、`get_variable_defs`、
  `get_motion_context`、`get_figjam`。
- 坑:不带 `nodeId` 时服务器跟随**桌面端当前选中节点**;`get_metadata '{}'` 不会列页面。
  父级节点拿不到(除非用户在 Figma 里选中它),所以设计稿里的"侧边栏宽度/外边距"无从得知。
- 图片以 base64 data 形式返回,落盘后用 `read_image` 看;`const imgX = "http://localhost:3845/assets/<hash>.svg"`
  可以直接 curl 下载,用来和用户给的素材做比对。

## 实现要点

- `MenuRight/Resources/BrandAssets.xcassets`:`menuright-logo` / `menuright-font` 两个 imageset,
  `preserves-vector-representation = true`,**不设** template(标记是渐变、字标是品牌青,必须保留自身颜色)。
  actool 实测:两者都产出 `Vector` rendition + `Image RGB` 位图兜底(不是 Monochrome)。
- `SidebarBrandHeader`(在 `SettingsComponents.swift`):`HStack(spacing: 8)` → 标记 39×39 +
  `VStack(spacing: 2)`{字标 120×18.7,`Text(version).font(.system(size: 13)).foregroundStyle(.secondary)`}。
  挂在侧边栏最上方(`SettingsRootView.sidebar` 里 `VStack { header; List }`),因此随侧边栏折叠、
  也在侧边栏材质背景内。
- `SettingsStore.sidebarVersionText`:用 `%@` 格式串 + bundle 版本(`sidebarVersionLine`,
  zh「版本 %@」/ en「version %@」)。
- `Scripts/check-icons.sh` 扩展为同时校验品牌资源:存在性、`preserves-vector-representation`、
  **不得** template、viewBox、孤儿 imageset,并交叉核对代码里的资源名。

## 两处刻意偏离设计稿(已写进 README,理由要保留)

1. **文字列宽**:设计稿的 `w-[146.699px]` 是设计师画框宽度(比里面 120pt 的字标还宽),
   按自然宽排版后整块 167pt 而非 193.8pt —— 可见像素完全一致,只是没有那个空的尾巴。
2. **版本行颜色**:设计稿是 `white`(深色稿),但本应用侧边栏跟随系统外观,浅色下白字不可见,
   故用 `.secondary`;要固定白色只需改一个修饰符。

另外品牌区左边距取 21pt(窗口边缘起 mark 墨迹 29.0pt),与导航图标列(29.5pt)对齐 ——
设计稿节点不含外边距,这是判断,不是稿子规定的;若要贴侧边栏内容边距,改成 14pt。
