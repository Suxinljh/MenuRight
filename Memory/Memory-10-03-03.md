## 为什么原来会「点了没反应」

- `Share/FileOperations/FileOperationDispatcher.swift` 的 customize 分支只做两件事:
  `ArchiveRequestCenter.shared.present(...)` + 返回 `.success(createdPath: nil)`,**不压缩**,把选择交给对话框。
- `ArchiveRequestCenter` 自己只把请求停在 `@Published var pending` 上,真正的显示靠
  `SettingsRootView` 的 `.sheet(item: $archiveRequests.pending)`。设置窗口一关,这个 view 不在层级里,
  `.sheet` 根本不存在 → 只有 `NSApp?.activate(ignoringOtherApps:)`,没有窗口可激活。
- **最坑的是日志**:`ARCHIVE dialog presented` 照样打印,而验证手册 §3.8 第 44 行的「失败时看什么」
  只写了这条日志 —— 所以「照手册验证」一直是**假阳性**。教训:验证证据要落在「用户看得见的东西」
  (窗口可见性),不要落在「代码走到哪一行」。

## 改法(4 个文件)

- `MenuRight/App/Settings/CustomCompressionSheet.swift`:新增 `protocol ArchiveDialogPresenting`
  (`show(_:)` / `close()`);`ArchiveRequestCenter` 增加可注入的 `presenter`,
  `activePresenter` = 注入的 presenter,否则 `guard NSApp != nil` 后返回 `CustomCompressionDialogWindow.shared`
  (**自动兜底,避免"忘记接线就静默没反应"这一类 bug 再次发生**);`present`/`dismiss` 转发给它。
- `MenuRight/App/Settings/CustomCompressionDialogWindow.swift`(**新**):`NSWindow` +
  `NSHostingController(CustomCompressionSheet(...))`;`styleMask = [.titled, .fullSizeContentView]`
  **故意不加 `.closable`**(取消/确定是唯一出口,照 `MenuRightFinder/ArchiveProgressWindow.swift` 的先例),
  `titleVisibility = .hidden`、`titlebarAppearsTransparent`、`level = .floating`、
  `identifier = "archive-dialog"`、`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]`;
  尺寸按 `fittingSize` 定,KVO 跟 `preferredContentSize` 重算(错误文案出现时会长高);
  `close()` 用 `DispatchQueue.main.async { orderOut }` **延后一拍** —— 关闭常常由对话框自己的按钮动作触发,
  立刻释放窗口可能在动作执行中析构。
- `MenuRight/App/Settings/SettingsRootView.swift`:删掉 `.sheet(item:)` 与 `@StateObject archiveRequests`。
- `MenuRight/App/MenuRightApp.swift`:DEBUG 自测钩子(MANUAL 里的那一键复现)。
- `MenuRight.xcodeproj/project.pbxproj`:新文件要**手工**注册 4 处(PBXBuildFile app+tests /

## 踩过的坑

- **测试进程里 `NSApp` 不是 nil**:原来 `CustomCompressionSheet.swift` 有句注释说"unit test 进程里没有
  NSApplication",本轮实测不成立 —— 只要进程内创建过 `NSWindow`,AppKit 就会惰性建出 `NSApplication`。
  后果:`activePresenter` 的兜底在测试里也会真的建窗口,既有用例
  `FileOperationDispatcherTests.testCustomCompressionIsExemptFromTheFormatSetting`(customize 分支)会留下一个窗口,
  所以在该文件 `tearDownWithError()` 里补了 `ArchiveRequestCenter.shared.presenter = nil` + `dismiss()`。
  **保留这套语义是故意的**:这样"没注入 presenter 就会用真实进程级窗口"能在单测里直接断言,而不是只能靠 app 自测。
- **签名沙箱版 app 写不了 `/tmp`、也写不了 `~/Desktop/...`**(报 "You don't have permission to save the file…"),
  PNG 只能往 App Group 容器写;自测里 `fixture=skipped(…)` 是正常的(自测停在对话框,不用那个源文件)。
- **xcodebuild 只转发 `TEST_RUNNER_` 前缀的环境变量**给测试进程,直接 `FOO=1 xcodebuild test` 不生效。
- **想把"透明背景的视图"渲染成能看的 PNG**:`NSBitmapImageRep.draw(in:)` 是 **copy** 语义,
  透明像素会把刚填好的背景重新打穿 —— 必须走 `NSImage.draw(in:from:operation:.sourceOver,fraction:)`。
  另一个坑:`NSRect.fill()` 在这个位图上下文里什么也不画,得用 `NSBezierPath(rect:).fill()`。
  最后写出的 PNG 是「深色窗口底 + 表单」,520×408 pt(2x = 1040×816),肉眼确认无裁切。
- `xcodebuild -target` 不能和 `-derivedDataPath` 同用(exit 64);跑完 xcodebuild 记得
  `Scripts/prune-launchservices.sh`。
- edit 工具:在既有代码块前插入内容时 `old_string` 别以换行结尾,否则会把下一行接到 `}` 后面。
