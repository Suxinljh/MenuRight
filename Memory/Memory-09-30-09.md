## 2. Finder 菜单图标的两个状态问题(**平台侧限制,已定位**)

用户原话:「hover后图标变白色 / 禁用图标变灰色」。**实测两条都没生效**:放大截图后确认,
高亮行(紫色底、白字)的图标是**黑色**,禁用行(灰字)的图标**也是黑色**——Finder 只把文字
按状态着色,图片是**原样绘制**。

排查证据链(都在本机实测,脚本在 /tmp,结论已写入 README 与验证手册):
1. appex 里的资源**本身就是纯模板**:`isTemplate=true`、`coloured=0`(无彩色像素)、24×24。
   → 不是"忘了设模板"。
2. `NSKeyedArchiver` 往返后 `isTemplate` **仍然保留**;`TIFFRepresentation` 往返后**丢失**。
   → 说明模板语义能否存活取决于 Finder 侧的接收/绘制方式,而实测结果是没有被采用。
3. 试过"绕开 `item.image`,改用 `NSAttributedString` + `NSTextAttachment`(模板图)"这条思路:
   离屏绘制验证 —— 白字场景下附件图标**仍是黑色**,文本系统也不给模板图上色。→ 这条路也不通。
4. 结论:**Finder Sync 扩展菜单里的自定义图片,无法实现按状态着色**(`NSMenuItem.image` 被原样 blit)。
   `isTemplate` 的着色契约在 AppKit 自家菜单里成立,在跨进程交给 Finder 绘制时不成立。

已给出的三个选项(等用户拍板,写进了验证手册 §3.5 第 14 项):
① 接受现状(图标三态黑色;悬停时在强调色上对比度一般);
② 把 6 个菜单图标换成 **SF Symbols** 再让用户在 Finder 里看一眼(唯一还没试的候选:
   symbol 在归档里保留 `NSSymbolImageRep`,所以"可能"被 Finder 按符号绘制;但同样无法本地验证);
③ 去掉 Finder 菜单图标(`applyIcon` + 扩展目录可一并删除;设置面板的图标着色正常,不受影响)。

## 教训 / 可复用

- **"图标出现了" ≠ "图标行为正确"**:上一轮我把"计划层映射有单测 + 资源打进 appex"当作验证,
  但真正的问题是绘制阶段的状态着色。用户在真机一眼就看出来了。
  → 涉及系统绘制的改动,必须把"系统怎么画"和"我们给了什么"分开验证,并明确写下未验证的部分。
- 看截图必须**放大**:缩略图里禁用行的黑色图标看着像灰色(我第一遍就读错了),放大后才确认是纯黑。
  `sips`/CoreGraphics 裁剪 + 4x 放大再 `read_image`,是这类判断的可靠做法。
- 排除法顺序建议:先证明"我们这边是对的"(isTemplate/无彩色像素)→ 再证明"传输/绘制阶段丢了"
  (归档 vs TIFF 往返)→ 最后才下"平台限制"的结论。这样给出的选项才有依据。
