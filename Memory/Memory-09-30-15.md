## 实现

- 规则放进可单测的 `OnboardingFlow`:
  `canAdvance(isExtensionEnabled:authorizedFolderCount:)` —— 第 1 步要求扩展已启用,
  第 2 步要求 ≥1 个已授权文件夹,第 3 步(汇总)永不阻塞;
  `blockedReasonKey(...)` 返回该显示哪条原因文案(或 nil)。
- 视图:`OnboardingView.footer` 里「下一步」`.disabled(blockedReasonKey != nil)`,
  按钮左侧显示一行 `.caption` 原因;新增两个文案键
  `.onboardingBlockedExtension`("需要先启用 Finder 扩展,才能继续。")/
  `.onboardingBlockedFolder`("需要至少授权一个文件夹,才能继续。")。
- **「稍后再说」保持可用**:拿不到权限的用户不能被卡死,这一点是刻意的。
- 附带交互修正:`.onReceive(didBecomeActiveNotification) { refresh() }` —— 用户去系统设置启用
  扩展后切回引导,状态与「下一步」自动解禁,不需要先点「重新检测」。

## 复盘要点

- 把"能不能继续"写成**纯函数**而不是散在视图里的 `if`,所以三条规则(含边界:汇总步不阻塞)
  都有测试;视图只负责禁用与显示原因。
- 像素测量在这件事上不可靠:禁用按钮仍带淡紫底色,按"饱和度"采样会误判为可用
  (实测 4215/8250 与可用态 4478/8250 差别很小)。**判断按钮状态要看渲染结果本身**(截图),
  或直接断言逻辑层,不要靠颜色统计。
