## 版权年份：先试“动态计算”，用户否决后改为常量

用户先问「年份可以改为按照当前年份动态计算吗，比如当前是2026，明年就是2026-2027」，实现到一半被否决：
**「不需要按照年份动态计算了，直接写2026」**。最终只改了硬编码年份（`Info.plist` 一行，+1/-1）。

期间试过的做法与结论（避免以后重走）：

- `Info.plist` 与 xcconfig 都不会求值 `date`，动态年份必须在别处算出来再喂给构建设置。
- 写了 `Scripts/copyright-year.sh`（`FIRST_YEAR=2026`，`--print [YEAR]`/`--range [YEAR]`，支持
  `MENURIGHT_COPYRIGHT_YEAR` 环境变量覆盖以便测区间分支），把 `MENURIGHT_COPYRIGHT_YEARS` 写进
  `Config/Version.xcconfig`，`Info.plist` 用 `$(MENURIGHT_COPYRIGHT_YEARS)` 替换；并给
  `MenuRight.xcscheme` 加了 `<PreActions>` 想让它每次构建前刷新。
- **实测结论：`xcodebuild -scheme` 不执行 scheme 的 pre-action**——把 xcconfig 预设成 `2026-2027` 后跑
  `xcodebuild -scheme MenuRight build`，日志里没有脚本执行痕迹，xcconfig 仍是 `2026-2027`，产物
  `.../MenuRight.app/Contents/Info.plist` 也就是 `2026-2027`。所以这条路对 `Scripts/release.sh`、
  `Scripts/install-dev-app.sh` 和 CI 全部无效（它们都走 `-scheme`）。
- 另外两条路当时判为代价过高，未采用：① 构建后脚本改写产物 `Info.plist`——本项目
  `ENABLE_USER_SCRIPT_SANDBOXING = YES`（pbxproj:1392、:1458），且
  `$(TARGET_BUILD_DIR)/$(INFOPLIST_PATH)` 已由 Process Info.plist 产出，声明为 output 会与它冲突；
  ② 构建脚本在构建前改写工作区源文件——xcconfig 在“构建设置解析”阶段就被读取，进程内改它只对下一次构建生效。
- 全部临时改动已回退：`Config/Version.xcconfig`、`Scripts/check-version.sh`、
  `MenuRight.xcodeproj/xcshareddata/xcschemes/MenuRight.xcscheme` 走 `git checkout --` 复原，
  `Scripts/copyright-year.sh` 删除，最终只剩 `MenuRight/Info.plist` 一行改动。
