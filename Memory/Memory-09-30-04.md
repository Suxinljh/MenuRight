### 关键技术决策

1. **不做 `.lproj`,用内存双语目录**:`Localization.table` 每个 key 同时存中英文,
   界面语言切换即时生效(无需重启),并有测试保证「每个 key 两种语言都存在」「%d 占位符一致」。
   这直接兑现了「通用设置 → 语言」这一项的承诺。Finder 菜单文案仍为英文硬编码,属下一阶段。
2. **单一 JSON 载荷存 App Group `UserDefaults`**(key `xin.ljhsu.MenuRight.settings`):
   便于扩展将来一次读取。解码宽容:缺字段回落到默认值;未知枚举成员(旧/新版本写入)被丢弃
   而不是让整份配置失效;类型错误或 JSON 损坏 → 加载为默认值(窗口永远能打开)。
   每次读取与写入都跑 `normalized()`(补齐新增类型、剔除 RAR 等不支持的项、钳制范围)。
3. **`SettingsStore` 不标 `@MainActor`**:沿用仓库既有 `IPCStatusCenter` 的写法
   (`@unchecked Sendable` + 主线程收口),避免 SwiftUI 视图初始化器与静态 `shared` 之间的
   隔离问题;`mutate` 在主线程同步应用(测试可同步断言),非主线程则 hop 到主线程。
   踩坑记录:`mutate` 的闭包必须声明 `@escaping`(非主线程分支要延后调用),
   命令行 `swiftc -typecheck` 没报出来,**xcodebuild 才报错** —— 结论:UI/并发相关改动必须用
   `xcodebuild` 验证,不能只靠独立 `swiftc` 检查。
4. **面板布局用 ScrollView + GroupBox 而不是 `Form(.grouped)`**:需要面板标题/副标题、
   分组页脚、徽章、行内按钮等自定义行;GroupBox 在深浅色下都是原生外观。
5. **诚实的「未实现」标注**:解压执行(P9)、Quick Look 高亮(P8)、Office/iWork 新建(P6-b)
   都只在界面里持久化配置并明说尚未生效;登录时启动用真实 `SMAppService`,失败就回滚并显示红字,
   不做假开关。
6. **新增 DEBUG 钩子 `MENURIGHT_SETTINGS_PANE=<category>`**:启动即打开指定面板,
   与既有 `MENURIGHT_SELFTEST_OPEN_TERMINAL` 风格一致,用于逐面板截图与人工复核;
   README 已记录用法。

## 踩坑与可复用结论

1. **`@Published` / `objectWillChange` 的时序**:`objectWillChange` 在 willSet 阶段发出,
   订阅者收到通知时读到的仍是旧值;收藏页原本用它做「重新检测」,已改为只在 `onAppear` 与
   显式按钮/增删操作后检测,顺带满足「菜单构建期零 IO」的既有约束。
2. **枚举的 Codable 是严格的**:`Set<NewFileType>` 里出现未知 rawValue 会抛错并使整份配置失效。
   改为按 `[String]` 解码再 `compactMap`,才做到跨版本宽容。
3. **`min`/`max` 在 Array 扩展内会解析成实例方法**,需要写 `Swift.min`/`Swift.max`。
4. **窗口尺寸**:`.frame(minWidth: 960, minHeight: 640)` 会作为窗口内容最小尺寸生效;
   窗口实际为 900×638 是上一版(旧 480 宽窗口)保存的 frame 恢复所致,故本次把最小尺寸调大。
   另:用 `screencapture -l <windowID>` 抓窗口时**窗口非 key 时控件会以灰色不活跃外观渲染**
   (开关看起来像关闭),需要先激活 App 再抓图,否则会误判为绑定错误。
