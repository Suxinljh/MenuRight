## 为什么菜单不放图标(实测证据,已写进 README 与验证手册)

Finder **原样绘制**扩展菜单的图片:
- 高亮行:文字变白,**图标仍是黑色**;禁用行:文字变灰,**图标仍是黑色**(放大用户截图确认);
- 资源本身没问题:`isTemplate=true`、无彩色像素、24×24;
- `NSKeyedUnarchiver` 往返保留 `isTemplate`,`TIFFRepresentation` 往返丢弃 → 传输/绘制阶段丢失契约;
- 富文本附件(`NSAttributedString` + 模板 `NSTextAttachment`)绕法离屏实测**同样不上色**。

**附带收益**:菜单里只要有一项带图片,Finder 就给整列留出图标位;去掉后我们的项与 Finder 自带项
(「新建文件夹」「显示简介」等)同缩进 —— 正好满足「文字前面不要有 padding」。
扩展侧 `FinderSync.addItem` 的标题字符串本身也没有前导空格(已 grep 确认)。

## 教训 / 可复用

1. **系统绘制的行为只能靠"系统侧事实"来判定,不能靠"我们给对了"**。上一轮我把"资源是模板 + 映射有单测"
   当作完成,但这只证明输入正确,没证明输出正确。
2. 下"平台限制"结论前要跑完排除法:输入正确 → 传输丢失(归档 vs TIFF)→ 替代路径也失败。
   这样给用户的选项才有依据,而不是"我试不出来"。
3. 放大截图是必须的:缩略图里禁用行的纯黑图标会看成灰色,我第一遍就读错了。
4. 回退也要先看 diff:`git diff --stat` + 过滤非图标行,确认这 4 个文件只含本次图标改动后再
   `git checkout`,避免连带回退用户改动(AGENTS.md 的红线)。
