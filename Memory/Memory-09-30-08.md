## 关键结论与踩坑

1. **沙箱 appex 读不到主 App 的 asset catalog** → 扩展必须有自己的一份图标(已实测:
   `assetutil --info` 在 `MenuRightFinder.appex/Contents/Resources/Assets.car` 里看到那 5 个名字)。
2. **Phosphor 与 Lucide 画法不同**:Phosphor 是 256 网格的**填充**路径, Lucide 是 24 网格 2pt **描边**。
   视觉上能凑成一族但不完全一致;Phosphor 的文件图标内嵌极小字号扩展名(TXT/HTML…),16pt 下只是装饰。
   保持各自原样(规格指定),如需可把 `AssetIcon(size:)` 调到 18。
3. **名字必须先验证**:Phosphor 用 `unpkg.com/@phosphor-icons/core@<ver>/assets/regular/<name>.svg`,
   `@latest` 会 302,必须 `curl -L`;Lucide 继续钉 tag(不带 v)。
4. 规范化脚本对两种格式都适用:只删**根标签**的 width/height、`currentColor` → `#000000`、
   断言除根标签与颜色外图形逐字节不变(Phosphor 本身没有 width/height,天然通过)。
5. **Finder 菜单图片未经自动化验证**:计划层单测能证明 icon 名映射正确,
   但 Finder 是否绘制扩展菜单项的图片只能人工看。README 与 runbook 都按 `Manual: PENDING` 记。

   大概率是笔误,但按规格实现;要我换成别的 Lucide 图标说一声。
