## 现象与根因

- 弹窗原文:`无法完成"解压压缩包"。Not a readable archive: the archive is password-protected, which this build does not support`。
- 根因:`ZipReader` 解析中央目录时只要看到通用位 bit0(加密位)就抛 `encryptedNotSupported`,链路把它翻成
  `archive_unsupported`。读侧从来没有"密码"这个概念 —— 密码本和加密压缩对话框都只服务于**写**。
- 约束:密码是秘密,**不能进 IPC 契约**(`FileOperationContract` 会被扩展与 App 双方使用,且扩展在沙箱里)。
  所以只能由主 App 在解压前解析密码 —— 而主 App 的 dispatcher 跑在 IPC 的后台**并发队列**上,弹框必须跳主线程。

## 设计与实现

三条规矩:

1. **写盘之前先定密码**:`ArchivePasswordResolver.resolve(archiveURL:prompting:)` 对每个归档先算一次
   `Resolution`(`notNeeded`/`resolved(String)`/`abandoned`),全部搞定后才开始写。任一 `.abandoned` →
   `FileOperationDispatcher` 立刻 `.failure(code: .cancelledByUser, message: "No password was given; nothing was extracted.")`
   —— 扩展端有 7 处 `guard code != .cancelledByUser` 会静默,用户不会看到错误框,也不会留下半个解压目录。
2. **验密码用真解密**:`ZipReader.validates(password:)` 挑**最小的那个可解加密条目**真解一次(而不是只信
   12 字节加密头里的校验字节 —— Info-ZIP 的流式写入者把 DOS 时间放在那两个字节上,信它会误判)。
   验不过就问,最多 `ArchivePasswordResolver.attempts = 3` 次,第 2 次起文案换成"密码不对",取消/留空即放弃。
3. **先密码本、后问人**:`automaticPasswords` 里的每一条都验;勾了「把密码存进密码本」就按
   `url.lastPathComponent` 记进钥匙串(与压缩对话框保存的键一致)。

动的文件:

## 坑

- **`NSAlert.runModal()` 期间主队列不会被 drain**:`DispatchQueue.main.asyncAfter` 在模态会话里**永不触发**
  (第一版自测因此挂死 4 分钟被 kill)。要观察/结束模态会话,用 `Timer` 并同时加进
  `RunLoop.Mode.default`/`.common`/`.modalPanel`,再 `NSApp.stopModal()`;另配 20 s 看门狗 `exit(2)`。
- **`NSAlert` 的 vibrancy 材质在窗口外 `cacheDisplay` 渲染成不透明白底**(浅色文字白底白字),所以
  "提示写了什么"用**视图树 dump** 断言,PNG 只看布局;alert 窗口 `title` 为空,别拿它判定。
- 自测夹具在**非 dispatch** 路径写盘也要自己取授权,否则沙箱报 "You don't have permission to save…":
  用 `FolderAuthorizationAccess.withAccesses(to:folders:)` 包住建目录/写源文件/压缩。
- app 自测的 PNG 只能写 App Group 容器(`~/Library/Group Containers/group.xin.ljhsu.MenuRight/`);
  沙箱版 App 写不了 `/tmp` 和 `~/Desktop`。探针目录 `/Users/suxin/MenuRight-ScopeProbe` 取证后要删。

## 仍不支持(有意)

- WinZip AES(method 99)与加密 7z:仍明确报"不支持/受保护",不会假装能解。
- 写侧与读侧都是自研 PKWARE 传统加密(ZipCrypto),兼容优先、强度有限——文档里已写明。
