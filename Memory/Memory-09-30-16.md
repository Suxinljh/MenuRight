## 用户问题的答案(模板 = 一个空白文件吗)

- **Word / Excel / PowerPoint 不需要任何模板**:由 `OOXMLDocumentFactory` 直接生成最小 OOXML 包。
- **Pages / Numbers / Keynote 需要各一份空白文件**:用户已提供并放进
  `MenuRight/Resources/Templates/`(`blank.pages` 88K / `blank.numbers` 134K / `blank.key` 446K),
  都是**普通 flat 文档**(不是 `.template` 包),复制走 `FileManager.copyItem`,字节一致。
- 缺模板时该类型**从右键菜单隐藏**并提示,不显示注定失败的菜单项(这是 P6 范围里写明的行为)。
- `blank.key` 自带 Keynote 主题素材(17 张母版 + 约 400K 图片),新建的 `.key` 也是这个体积;
  想更小可另存纯白主题覆盖。这一点已写进 `Resources/Templates/README.txt` 与验证手册。

## 实现

1. `Shared/FileOperations/ZipWriter.swift`:local header + DEFLATE(压缩不划算则 STORE)+ CRC32 +
   central directory + EOCD;**不支持 ZIP64 并显式拒绝**;固定 1980-01-01 时间戳 → 同输入同字节。
2. `Shared/FileOperations/OOXMLDocumentFactory.swift`:docx 5 部件、xlsx 6 部件、pptx 11 部件,全部是
   字符串常量(不打包任何 .docx 模板,避免带进用户没要的格式)。
3. 线上契约(纯增量,`version` 仍 1):`OperationKind.createDocument` / `.createFromTemplate`,
   `OperationArgs.documentKind`,错误码 `templateMissing` / `unsupportedDocumentKind`。
   扩展只发"要哪一种",生成与复制都在主 App;`createDocument` 生成后走与 `createFile` 相同的授权门。
4. `DocumentTemplateCatalog`:模板文件名映射 + `canCreate` + `publishAvailability`(App Group 单键 JSON)。
5. 扩展:`NewFileKind` 扩到 12 项(rawValue 与 `NewFileType` 对齐,有测试钉住),
   `NewFileKind.available(from:)` 过滤;`menu(for:)` 读 availability(cfprefsd 查询,不做文件扫描);
   **没有 payload → 只给文本 6 项**(保守回退)。
6. 设置界面:去掉"P6-b 计划中"角标,改为缺模板时显示「缺少模板」+ 卡片里列出缺少的文件名;
   `NewFileType.isShipped` → `requiresTemplate` / `isGenerated`。
7. pbxproj:`MenuRight/Resources/Templates` 注册为 **folder reference**,以后丢文件进去不用改工程;
   已确认签名产物里存在 `MenuRight.app/Contents/Resources/Templates/`。
8. `Scripts/verify-document-generation.sh`:把**仓库里的源文件**编成 CLI → 生成到
   `build/verification/p6b/` → ZIP/XML/内容类型/关系目标/格式结构校验 + 可选独立读入器
   (`MENURIGHT_VERIFY_PYTHON=/path/to/venv/bin/python`)+ QL 缩略图像素采样。

## 复盘要点(全部实测,不是推断)

1. **`import zlib` 在 macOS Swift 里可用**,但 `compress2` 产出的是 zlib 包装(`78 9c`),
   ZIP 需要 raw deflate:必须调 ABI 级
   `deflateInit2_(&s, level, Z_DEFLATED, -MAX_WBITS, 8, strategy, ZLIB_VERSION, sizeof(z_stream))`
   (宏 `deflateInit2` 不会导入 Swift)。`zlib.crc32` 可直接用。
2. **PPTX 母版缺 `<p:bg>` → 幻灯片渲染成灰色 (172,178,187),而所有结构校验全部通过。**
   我用本仓库代码复现了该坑(QL 缩略图中心像素 = 172,178,187),加上
   `<p:bg><p:bgRef idx="1001"><a:schemeClr val="bg1"/></p:bgRef></p:bg>` 后变白。
   现在验证脚本用 Pillow 采样缩略图中心像素,白 + 16:9 才 PASS —— 这是唯一能自动发现它的办法。
3. **xlsx 没有 theme 部件时 `styles.xml` 不能引用 `theme="1"`**,改成 `<color rgb="FF000000"/>`
   (解析不到的主题色引用是 Excel"需要修复"的经典触发点)。
4. `[Content_Types].xml` 必须是第一个 entry;每个部件都要被 Default/Override 覆盖;`r:id` 必须有
   对应关系 —— 三条都进了自动化校验与单测。
5. 参考材料由并行 subagent 产出(`/tmp/p6b-reference/SPEC.md`,逐部件 XML + 23 条陷阱表,
   它自己用 Apple `Office.qlgenerator`/textutil/三个 Python 库做了验证)。我只采纳了**能在本机复现**的
   两条结论(灰底、xlsx 主题色);其余按"未实测"对待,不写进结论。
6. 它的最小 docx 只有 3 个部件、我的有 5 个(多 styles.xml):验证器都接受,保留更完整的版本。
