## 结论：计划层面基本全部落地，但有 4 个真实缺口

### 1. 设置 → 文件权限：三个开关一个都没接线（最严重）

- `FilePermissionSettings` 有 `allowedActions` / `restrictToAuthorizedFolders` / `confirmDestructiveActions`（`Shared/Settings/MenuRightSettings.swift:206-240`），面板 11 个动作开关在 `MenuRight/App/Settings/Panes/FilePermissionSettingsView.swift:12-14,21-29,45`。
- 全仓库生产代码里 `allowedActions` / `isAllowed(` / `restrictToAuthorizedFolders` / `confirmDestructiveActions` **零调用点**（只有定义、面板与单测 `MenuRightTests/MenuRightSettingsTests.swift:96-104`、`SettingsStoreTests.swift:201-204`）。
- 扩展侧：`MenuRightFinder/` 内没有任何 `FileAction`/`allowedActions` 引用；菜单项在 `FinderMenuBuilder.swift:380-419` 无条件生成。
- 主 App 侧：`FileOperationDispatcher` 只读 `archives`（`Shared/FileOperations/FileOperationDispatcher.swift:58`），授权是**无条件**强制的（6 处 `NOT_AUTHORIZED`）。
- 代码注释自己写明这是"以后再用"：`MenuRightSettings.swift:144-147`「The set is used as a menu filter later; nothing here performs the operation itself.」
- 而这正是计划 §2「P2 菜单可见性配置 ✅ 可行：扩展按设置裁剪」那一项，未实现。历史 Memory 已记录过（`Memory/Memory-09-30-12.md:54`、`Memory-09-30-13.md:31`、`Memory-09-30-16.md:75`，当时叫 P7-b），**至今未接线**。
- README:85 仍宣称它决定「哪些操作允许出现在菜单里」，无任何说明。

### 2. 设置 → 新建文件：启用类型 / 顺序 / 默认文件名 都到不了菜单和文件

- 主 App 只发布"模板是否存在"这一份 payload：`Shared/FileOperations/DocumentTemplateCatalog.swift:92-107` 用 `NewFileType.allCases.filter { canCreate }`，**完全忽略 `settings.newFile.enabledTypes` 与 `types` 顺序**；唯一生产调用点 `MenuRight/App/MenuRightApp.swift:34`。
- 扩展只读这份 payload：`MenuRightFinder/FinderSync.swift:114`（`NewFileAvailability.readFromAppGroup()`）→ `FinderMenuBuilder.swift:58-61`。扩展从不读设置 JSON。
- 文件名硬编码：`FinderMenuBuilder.swift:104-106` `defaultName = "Untitled.\(fileExtension)"`，三种类别都把 `kind.defaultName` 当 `name` 发给主 App（`FinderSync.swift:356-388`），所以 `baseName` 永不生效——与 `MenuRightSettings.swift:245-247` 的注释「The extension appends the kind's extension」相矛盾。
- 面板自己的「菜单预览」却按 `enabledTypes`/`baseName` 渲染（`MenuRight/App/Settings/Panes/NewFileSettingsView.swift:87,103`），容易让人以为已生效。
- `Memory/Memory-09-30-16.md:75` 记过这个缺口（并称"README 已如实标注"），但 README 实际没有相应说明。

### 3. 终端 App 可配置：未做

计划 P6 第 2 条写「终端 App 可配置，默认 Terminal」；实际 `Shared/FileOperations/SystemOpener.swift:57-61` 硬编码 `/System/Applications/Utilities/Terminal.app` 与 `/Applications/Utilities/Terminal.app`，无设置字段、无 UI。

### 4. 模板目录可选覆盖：未做

计划 P7 写「模板目录可选覆盖」；`NewFileSettings` 只有 `baseName`/`types`/`enabledTypes`（`MenuRightSettings.swift:244-250`），`DocumentTemplateCatalog.bundledDirectory:36-38` 固定指向 `Bundle.main.resourceURL/Templates`。

## 计划里"故意不做 / 做不到"的（不算漏做，但要知道）

- RAR 解压：`ArchiveMemberSource.swift:81-82` 主动 throw；名称检测也排除（`ArchiveFormats.swift:39`）；设置里灰行（`MenuRight/App/Settings/Panes/ArchiveSettingsView.swift:73-80`）。决策 D5-R1。
- 创建 XZ：`ArchiveCompressor.swift:74` writableFormats 只有 zip/7z/tar/gzip/bzip2，`:419-420` 对 `.xz`/`.rar` throw；XZ 只能解（`ArchiveMemberSource.swift:77,241-317`）。
- WinZip AES 的 zip 读取：`Shared/FileOperations/ZipCrypto.swift:14-16` 只支持传统 ZipCrypto。
- ZIP64：`ZipWriter.swift:24-26` 明确拒绝（>4GB / 条目过多）。
- 7z 不写目录条目（空目录丢失）、加密 7z 走临时目录导致符号链接不落盘：README:153-154。
- P10 快捷键：全仓库无 `NSEvent.addGlobalMonitor*`/`RegisterEventHotKey`/Carbon 等；计划自己写「建议降级或放弃」（C8）。
- 侧边栏右键 / ToolbarItemMenu：`FinderSync.swift:97-99` 只处理 items 与 container 两种 kind。
- `.ts`/`.rs`/`.go`/`.sql` 不被 QL 接管：`MenuRightCodePreview/Info.plist:42-61` 只有 17 个 UTI；`MenuRight/Info.plist` 与 `MenuRightFinder/Info.plist` 无 `UTImportedTypeDeclarations`。QL 缩略图 provider 未做。
- 新建后内联重命名（C3）、顶层"与 MenuRight 同级"菜单（C1）、压缩包默认打开方式：均按约束不做。
- 「锁定/解锁同时常驻」是**有意为之**（手册:118 已写明），与计划菜单表「含锁定项时才显示解锁」不同。
- 计划 D3-A 说选中态"平铺零二级"，实际 7 个核心项平铺，但 `解压 ▸` / `压缩 ▸` 仍是二级（`FinderMenuBuilder.swift:410,417`）。
