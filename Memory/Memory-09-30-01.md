# Memory 2026-09-30-01 - Audit remediation (H1/H2/H3 + M/L findings)

## Scope

Implemented the fix plan for the audit findings list, high to low priority, on
the MenuRight checkout (`/Users/suxin/Suxin/code/app/MenuRight`). No third-party
dependencies were added; App Sandbox and the existing bookmark authorization
model were preserved.

## Completed work

### H1 - read deadline + main-thread blocking (fixed)

- `UnixSocketTransport.readExactly`/`writeExactly` now wait with `poll()`
  against a wall-clock deadline **before** each syscall, instead of checking a
  deadline after `read()` returned. This holds even when no socket option could
  be applied, which was verified by test (`testDeadlineHoldsWithoutAnySocketOptions`).
- Timeouts are parameters now: `defaultTimeoutSeconds = 5`, `connectTimeoutSeconds = 2`;
  `readFrame`/`writeFrame` share one deadline for prefix + body.
- `SO_RCVTIMEO`/`SO_SNDTIMEO`/`SO_NOSIGPIPE` are applied as defence in depth.
  `SO_NOSIGPIPE` is load-bearing: without it, writing to a closed peer raises
  SIGPIPE and kills the process.
- The listener fd is set `O_NONBLOCK` explicitly (`DispatchSourceRead` does not
  do it), accepted fds are forced back to blocking mode, and both get timeouts.
- The extension no longer performs IPC on the main thread: `FinderSync` has a
  private serial `ipcQueue`, the `init` ping is fire-and-forget, and every menu
  action dispatches the request on that queue, returning to the main queue only
  to present the alert.

### H2 - socket trust (fixed)

- `listen(on:)` no longer unconditionally unlinks the path. It refuses to touch
  a non-socket file or a socket owned by another uid, and probe-connects first:
  a live listener is never clobbered (second instance refuses to start).
- `chmod(path, 0o600)` now happens **after** `bind()` (the old `fchmod` ran
  before the fd had any filesystem node, so it could not set the mode).
- The extension verifies the connected peer's code signature against the main
  app's designated requirement before sending any bytes. `PeerIdentity.verify`
  was generalized (`requirement:expectedTeamIdentifier:` with defaults) and
  exposes `extensionRequirementString` / `mainAppRequirementString`.
- `MainAppIPCServer` accepts injected `socketURL`, dispatcher, and
  `peerVerifier` so the gate is testable.

### H3 / M3 - stale bookmarks (fixed)

- `FileOperationDispatcher` now passes a `persistRefreshedBookmark` hook for both
  single-target and multi-target operations; the hook was previously never
  supplied in production, so every stale bookmark was an unconditional failure.
- `FolderAuthorizationAccess` has one shared `startAccess(...)` helper used by
  `withAccess` and `withAccesses`, so the stale policy is identical in both.
- `FolderAuthorizationStore` RMW cycles are serialized with an `NSLock`
  (the dispatcher runs on a concurrent queue; `update`/`add` could lose writes).

### M1 / M6 - path containment (fixed)

- New `FileOperationDispatcher.validateName` rejects empty, `.`, `..`, `/`, `:`,
  NUL, and >255-byte names (leading dots allowed).
- `FileOperationService` re-checks `AuthorizedURLResolver.isDirectChild` right
  before writing.
- `AuthorizedURLResolver.contains`/`isDirectChild` are the single component-wise
  containment implementation; bookmark resolution must now actually contain the
  target, otherwise `authorizationRequired` (metadata match is only a pre-filter).

### M2 - team binding (fixed)

- Requirement strings now include `certificate leaf[subject.OU] = "<team>"`.
- The expected team id is injected at build time via the
  `MenuRightExpectedTeamIdentifier` Info.plist key (`$(DEVELOPMENT_TEAM)`) in both
  bundles, with a literal fallback for the test bundle.

### M4 - regression net (added)

- New test files: `UnixSocketTransportTests`, `FileOperationDispatcherTests`,
  `IPCProtocolTests`, `FileOperationContractTests`, `PeerIdentityTests`,
  `IPCIntegrationTests`, plus containment cases in `AuthorizedURLResolverTests`.
- Test target membership extended with `UnixSocketTransport`, `IPCProtocol`,
  `MenuRightIPC`, `PeerIdentity`, `MainAppIPCServer`, `ExtensionIPCClient`.
- `FileOperationDispatcher.mapError`/`mapAuthError`/`canonicalize`/`validateName`
  made internal for testing.
- Suite grew from 95 to 159 tests.

### M5 / M7 / L1-L9 (fixed)

- README rewritten to P5-1 (main app is the sole writer, IPC trust model,
  socket mode, stale renewal, Swift 5 language mode decision, manual gate A-J,
  and the signing caveat for headless test runs).
- `MenuRightIPC`: removed `buildMarker`, `endpointFilename`, `MenuRightXPCService`
  (all unreferenced); header comment corrected ("only ping is implemented" was
  stale); `appGroupIdentifier` is now the single source of truth.
- `LifecycleDiagnostics.record` uses `O_APPEND` + a 1 MiB cap with one rotation.
  The old fallback `Data.write(to:)` **truncated the whole log file**.
- `MainAppIPCServer`: cancel handler captures the fd by value (a stop/start cycle
  can no longer close the new fd), lifecycle state confined to `acceptQueue`,
  `AppDelegate` no longer reads `isRunning` across threads.
- Extension target: removed the two file entitlements and the ten now-unreachable
  write/authorization sources, enforcing "main app is the only writer" in the
  build graph.
- Fixed the two missing-backslash interpolations in `SecurityScopedBookmark`
  (the bookmark diagnostics were printing literal text).
- Removed unused `FileOperationError.from(_:context:)` parameter; deleted the
  dead non-delegated `OperationPresenter` functions and `FinderSync.describe`.
- Removed the unreferenced duplicate `MenuRight/MenuRight 2.icon/` (byte-identical
  to the kept `MenuRight.icon`; `git rm -r --cached` + delete).
- `FolderAccessView` caches per-folder `AuthorizationStatus` in `@State`,
  computed on explicit reloads instead of inside `body`.

## Out-of-scope items addressed after the fixes (Release + concurrency)

Release signing / hardening:
- `Release` builds signed and successfully with `-allowProvisioningUpdates`.
- Found: **Release also carried `get-task-allow=true`**, because the Xcode-injected
  base entitlements are applied to every configuration. (Note: `plutil -extract`
  cannot query that key — `.` is a key-path separator; use `plutil -p`.)
- Fixed by adding `CODE_SIGN_INJECT_BASE_ENTITLEMENTS = NO` to the two **Release**
  configurations (app + extension). Verified: Release entitlements are now only
  sandbox + App Group (+ the app's file entitlements), hardened runtime
  (`flags=0x10000(runtime)`) is on, the appex passes embedded-binary validation,
  and Debug still has get-task-allow so Xcode can attach.
- Still not distributable: a Personal Team means a development profile; shipping
  needs a paid Apple Developer Program (Developer ID / Apple Distribution).
- Also fixed a real leftover from my own refactor: an unused
  `targetComponents` in `AuthorizedURLResolver.folderMatching` (found by
  `SWIFT_STRICT_CONCURRENCY=complete`).

Swift strict concurrency:
- Measured with `SWIFT_STRICT_CONCURRENCY=complete`: 21 warnings, 0 errors
  initially; after adding justified `Sendable` conformances (wire contract,
  extension outcomes, ScopedAccessConfiguration, FolderAuthorizationStore,
  FileOperationDispatcher, MainAppIPCServer) and removing the tuple-splat
  pattern note: **14 warnings (7 unique), 0 errors**.
- Residual is one design decision: `NSAlert` main-actor isolation in
  `OperationPresenter` (not annotated) and `FinderSync.swift:400`'s non-Sendable
  handler closure. Deliberately deferred: fixing it requires choosing
  FinderSync's isolation model, and the only verification is the still-pending
  Finder gate. Language mode remains 5.0.
