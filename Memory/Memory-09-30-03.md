## 这次会话修掉的 4 个真实缺陷(按发现顺序)

### 1. `cp -R` 复制 Xcode 构建的 .app 会被内核杀死

- 症状:界面一直 `Finder Extension: Disabled`;被误判为"拿不到权限"(实际 Folder Access 已 Authorized)。
- 证据:`.ips` 里 `SIGKILL (Code Signature Invalid)` / `namespace=CODESIGNING` /
  `indicator=Taskgated Invalid Signature`。而 `codesign --verify --deep --strict` 对副本仍报
  "valid on disk" —— **静态校验查不出来**。
- A/B 实测(同一构建):DerivedData 直接运行 = ALIVE;`ditto` 复制 = ALIVE;**`cp -R` 复制 = 必被杀死**。
  Debug 构建的调试 dylib 依赖硬链接,`cp -R` 会解开它们。
- 附带发现:8/30 那份旧副本的 provisioning profile 已于 **2026-09-06 过期**
  (Personal Team profile 只有 7 天)。
- 修复:`Scripts/install-dev-app.sh` —— 签名构建 → 校验产物签名 → **ditto 安装** →
  **验证安装副本真能启动** → 注册/启用扩展 → 打印系统状态。

### 2. 扩展无法加载:替换 .app 后 Finder 一直用缓存的插件列表

- 证据:MenuRight 从 `pluginkit -m -p com.apple.FinderSync` 里**彻底消失**(只剩其它 app),
  且 14:48 之后 Finder **再也没有调用过 `menu(for:)`**;但 `pluginkit -e use` 报告成功。
- 修复:脚本增加 **`killall Finder`**,并改为轮询 `pluginkit -m -p com.apple.FinderSync`
  直到出现且为 `+` 才报成功。

### 3. 扩展的 IPC 对端校验在沙箱内根本跑不起来

- 症状:所有委托操作静默失效(`Open Terminal 无效`)。
- 证据(同一日志,相距 15ms):
  `MenuRightFinder: live peer code unavailable / REJECTED … OSStatus=100001`
  vs `MenuRight: MAIN-IPC peer OK … team=92X76S5UFL`。
- **结论:沙箱化的 appex 对任何对端都用不了 code-signing API**
  (`SecCodeCopyGuestWithAttributes` 与 `SecStaticCodeCreateWithPath` 都返回 100001);
  同一个调用在主 App 里完全正常。`proc_pidpath_audittoken` 在扩展里**可用**。
- 修复:分层校验,只有前一层不可用才降级,且"校验过但不过"一律拒绝:
  1. audit token → live SecCode → requirement(主 App 侧完全未改);
  2. live 不可用 → 该路径的静态签名校验;
  3. 两者都不可用(本机现状)→ **内核报告的 peer 可执行路径**精确比对
     (期望值由自身 bundle 推导),并每次记录降级警告。
  这样"unlink socket 后自己 bind"的攻击者必须运行**我们安装的那份可执行文件**。
- 踩到的两个坑(都有单测):
  - `Bundle.main.bundleURL` **带尾部斜杠**,三连 `deletingLastPathComponent()` 会多退一级 →
    派生值为 `nil` → **静默关闭校验**(这就是第一次修复后仍然全被拒的原因);
  - 扩展沙箱内 `Bundle(url:)` 读不到主 App 的 Info.plist → 增加标准布局兜底
    `conventionalExecutablePath`(`<App>.app/Contents/MacOS/<App>`)。

### 4. 重启竞争:新实例只 bind 一次,失败就永久不可达

- 症状:重启 App 后点 Open Terminal 无反应,之后菜单好像"消失"。
- 证据:
  ```
  15:11:08 35096(新): start(): another listener is already running   ← 旧实例 34473 仍持有 socket
  15:11:15 34473(旧): listener stopped + 取消链接 socket
  15:11:19 35125(扩展): connect() failed: No such file or directory   ← 无人监听
  ```
- 修复:bind 遇占用改为退避重试(0.5s × 60),成功写 `listening after N retry/retries`;
  `stop()` 让待重试循环停下;`applicationDidBecomeActive` 在预算耗尽后重新武装(自愈)。
- 又抓到:`MenuRightApp` 在 `willFinishLaunching` 与 `didFinishLaunching` **各调一次 `start()`**,
  造成两条并发重试链、尝试次数翻倍(实测恰好在第 60/60 次才成功)。已用 `bindRetryScheduled` 保证单链。

### 5. Open Terminal 本身:沙箱禁止直接启动别的 App(Spike S1 结论)

- 证据:
  ```
  NSCocoaErrorDomain 256 / NSOSStatusErrorDomain -54 "permErr: permissions error (on file open)"
  _LSFunction=_LSOpenStuffCallLocal, NSURL=file:///System/Applications/Utilities/Terminal.app/
  ```
- 可用方案:**Terminal 的 Finder 服务 "New Terminal at Folder"**,通过
  `NSPerformService(name, privatePasteboard)` 交给 Services 基础设施执行(动作发生在 Terminal 进程内)。
- 实测:`NSPerformService("New Terminal at Folder", pb)` 返回 true
  (中文标题返回 false;**英文默认标题在中文系统上同样有效**);
  新 shell 的父进程链 `Terminal.app → login → -zsh`,**cwd 等于目标目录**。
- 已改为服务优先、直接启动作兜底,并把 permErr 从用户可见信息里剔除。
