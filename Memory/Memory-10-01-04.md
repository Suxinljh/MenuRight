# Memory — 2026-10-01 (04)

本轮:排查「install-dev-app.sh 装的包启动后没有权限」。**根因不是权限**,但确实存在一个真实的
"多副本冲突",已清理并固化进脚本。

```
Automated: PASS  (install-dev-app.sh bash -n;注销循环在植入假副本上实测生效)
Manual:    PENDING(需要用户确认屏幕上到底是哪一条提示 —— 见文末)
```

## 查实的事实

1. **LaunchServices 里注册了 22 份 `MenuRight.app`**(13 份悬空:目录早没了、注册还在),
   来源是 Xcode 的 `RegisterWithLaunchServices` 构建步骤 + 历次 `-derivedDataPath` 构建
   (`build-*/`、`build/dd-*/`、`build/releases/`) + 脚本自己的备份目录 `~/MenuRight-old-copies/`。
2. **其中一份被 pluginkit 主动拒绝**:
   `build/Build/Products/Debug/MenuRight.app/.../MenuRightFinder.appex` 的 appex **没有沙箱**,
   系统日志里是 `rejecting; Ignoring mis-configured plugin …: plug-ins must be sandboxed`(10:06:36)。
3. 09:03 时**确实有旧副本在运行**:tccd 日志里出现
   `build/releases/MenuRight.app/Contents/MacOS/MenuRight`。
4. 同一时段 app 自己的诊断:扩展是**启用**的(pluginkit `+`、`isExtensionEnabled=true`)、
   IPC 对端校验通过、授权文件夹有 `/Users/suxin` 与 `~/Desktop`。
   **日志里没有任何 NOT_AUTHORIZED / 权限失败。**
5. 唯一一次失败是 10:03:22 的 `archive_too_large`:用户在 `~/Suxin/code/app` 里选了 3 个工程目录
   点「压缩为 ZIP」→ 超过 1024 MB 上限被拒。这是体积守卫,不是权限。
6. `kTCCServiceAppleEvents requires entitlement com.apple.security.automation.apple-events but it is
   missing`(应用调 `isExtensionEnabled` 触发)**不是新问题**:09-30 有 41 次、10-01 有 14 次,
   且该调用仍然返回 true。

## 做了什么

- **一次性清理**:`lsregister -u` 注销 21 份陈旧副本,只留 `~/Applications/MenuRight.app`;
  重新 `lsregister -f -R -trusted` 注册;pluginkit 不再拒绝。
- **固化进 `Scripts/install-dev-app.sh`**(第 6 步开头):每次安装前扫出所有已注册的 `MenuRight.app`,
  除刚安装的那份外全部注销,并打印注销数量。这样 Xcode 每次构建重新注册的 DerivedData 副本
  也会在下次跑脚本时被清掉。
- **踩到并修掉一个自己的 bug**:`sed -n 's/^…path:…\(.*\)[[:space:]]*(0x…)$/\1/p'` 里 `\(.*\)`
  是贪婪的,会把路径**末尾的空格**一起捕获,于是后面 `grep 'MenuRight\.app$'` 永远匹配不上——
  脚本会静默什么都不做却看起来正常。改成 `\(.*[^[:space:]]\)` 后实测能匹配、能注销。

## 用户确认的症状

「系统设置 → 隐私与安全性 → 扩展里有问题」——即开关找不到/打不开或指向别的副本。
这与多副本冲突完全吻合(系统设置就是从 pluginkit 的注册表读列表的),**不是沙箱/授权问题**。

## 新增 `Scripts/prune-launchservices.sh`

清理逻辑从 install-dev-app.sh 里抽出来做单一实现(安装脚本改为调用它),这样**在 Xcode 里
构建完也可以单独跑一次**——因为 Xcode 的 `RegisterWithLaunchServices` 是内置步骤,
`-showBuildSettings` 里没有任何开关能关掉它,每次构建都会把 DerivedData 那份重新注册。

实测:干净状态报 `clean (1 registration)`;植入一份假副本后报
`unregistered /private/tmp/…/MenuRight.app` 并保留安装副本。

踩坑记录(留给以后写 shell 的人):macOS 自带 **bash 3.2**,没有 `mapfile`/`readarray`,
必须用 `while read` + 进程替换(用管道会让计数器丢在子 shell 里)。
