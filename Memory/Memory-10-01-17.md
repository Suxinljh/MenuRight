## 检查更新:原生实现,零新依赖

- `MenuRight/App/Updates/UpdateRelease.swift`(纯逻辑,可单测):GitHub payload 解析
  (`tag_name`/`name`/`body`/`html_url`/`assets`,**拒绝 draft 与 prerelease**,取第一个 `.zip` asset)、
  版本比较(`UpdateVersion`,数字分段比较,`1.10 > 1.9`,缺位按 0,忽略 `-beta` 后缀)、
  策略(`UpdatePolicy`:24h 节流、"跳过此版本"、更新说明截断)。
- `MenuRight/App/Updates/UpdateChecker.swift`:`GET https://api.github.com/repos/Suxinljh/MenuRight/releases/latest`
  (`Accept: application/vnd.github+json`,超时 15s,User-Agent 带版本号);`ObservableObject` 发布
  `.idle/.checking/.upToDate/.updateAvailable/.failed`;手动检查报告失败,启动检查**静默失败**。
  **不做下载/替换**——注释里写明了原因(需要签名校验、原子替换、重启,那是 Sparkle 的职责)。
- `MenuRight/App/Updates/UpdatePrompter.swift`:启动时发现新版本弹一次 `NSAlert`
  (当前版本 / 最新版本 / 说明节选;按钮 前往下载 / 跳过此版本 / 稍后)。
- 设置:`GeneralSettings` 新增 `automaticallyChecksForUpdates`(默认 **true**)、`skippedUpdateVersion`、
  `lastUpdateCheck`;`init(from:)` 用 `decodeOr`/`decodeIfPresent`,**旧 payload 默认保持开启**(有单测钉住)。
- UI:通用设置新增「更新」分组(开关 + 立即检查 + 状态行 + 发现新版时的说明与两个按钮)。
- 启动钩子在 `AppDelegate.applicationDidFinishLaunching`(与 `FavoriteIconBootstrap` 并列),不依赖窗口是否打开。
