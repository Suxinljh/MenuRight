## 根因(上一轮修阻塞时引入的外观问题)

用户截图:提示框是英文 + 多出「不再显示此信息」勾选框 + 一个空按钮 + 一个帮助按钮。

**不是我们加了按钮,是没让 AppKit 把不用的槽位收起来。**
`NSAlert` 只在**模态**展示(`runModal()` / `beginSheetModal(for:)`)时跑那次布局整理,
而上一轮为了不阻塞扩展主线程,改成了直接 `alert.window.orderFront` → `NSAlertPanel.nib`
里这次用不到的控件全露出来了。那句话的出处也查到了:它是
`/System/Library/Frameworks/AppKit.framework/.../NSAlertPanel.nib` 自带的。

**可复用的验证手法(不用截图)**:写个小程序把 `alert.window.contentView` 递归 dump 出来。

```

               _NSAlertButton title="好" / title="" (空) / title="打开 MenuRight"
               NSButton frame={{224,286}} (帮助按钮)     面板 260x328
layout() 之后: _NSAlertButtonsStackView 里只剩 title="好" 与 title="打开 MenuRight"
                                                        面板 260x253
```

## 修法

- `presentTitleOnMain` 里显式调用 `alert.layout()`,并加 `showsSuppressionButton = false`、
  `showsHelp = false`、`hideUntitledButtons(in:)` 三重兜底。
- **文案全部本地化**:`OperationPresenter` 改成走 `Localization.text(key, language:
  FinderMenuLanguage.resolve())`,跟随「通用设置 → 界面语言」,与菜单标题同源。
  新增 30 个 `presenter*` key(中英双语)。`presentDelegatedItemFailures` /
  `presentDelegatedArchiveFailure` 的 `action` 参数从英文 `String` 改成 `StringKey`,
  调用点传 `.presenterActionExtract` 等。
- **两个按钮**:「好」+「打开 MenuRight」(`NSWorkspace.openApplication` 打开宿主 App,
  失败只记 NSLog)。只有"主 App 未运行"这一条提供第二个按钮。
- **target 成员**:`OperationPresenter.swift` 原本也被编进主 App target,但主 App 从不引用它
  (grep 确认)。已从主 App target 的 Sources 移除,这样它能直接用扩展的
  `FinderMenuLanguage`,不必为它单开注入路径或复制语言解析逻辑。

## 踩坑

- `Self.diag.log("ACTION \(action, ...)")` 里 `action` 从 `String` 变成 `StringKey` 后,
  os_log 的插值要求 `NSObject`/`CVarArg` → 必须写 `action.rawValue`(8 处)。
- 新增 key 后 `LocalizationTests` 会自动校验「中英文都有」「占位符一致」,这次它把
  30 个 key 全过了一遍,没有额外工作。
