## 四个实测发现的真问题(都不是推断)

1. **`GroupBox` 的内边距本身就不对称**:实测水平 ≈7pt、竖直 ≈11pt;再叠加我给每行加的
   `.padding(.vertical, 7)` → 竖直 ≈20pt vs 水平 7pt,这就是"上下左右不一致"的根因。
   解决:**不再用 `GroupBox`**,`SettingsGroup` 自绘卡片:
   `.padding(cardInset)` + `.frame(maxWidth: .infinity)` + `RoundedRectangle.fill(.quinary)`;
   行自身不再有竖直内边距,卡片内唯一的竖直节奏来自 `SettingsRowDivider`(上下各 8pt)。
   于是单行卡片高度 = 12 + 24 + 12 = **48pt**(实测吻合)。
2. **开关行用裸 `Toggle`**:`Toggle` 宽度随内容 → 整张卡片被压到 **150pt**,开关也贴在文字旁边。
   解决:`HStack { label; Spacer; Toggle("", isOn:).labelsHidden() }` → 卡片恢复满宽,开关贴右。
3. **固定宽度 frame 里的弹出按钮是左对齐的**:语言选择器 `.frame(width: 190)` 里,popup 按钮
   停在 frame 的**前缘**,实测距卡片右缘 **57pt**。解决:`.frame(width: 190, alignment: .trailing)`。
   修复后选择器与开关的右缘都在距卡片右缘 **11.5pt**(目标 12pt,差值是抗锯齿)。
4. **`role: .destructive` + `.tint(.red)` 在 macOS 的 `.bordered` 按钮上不上色**(实测渲染成灰字)。
   解决:颜色显式写到 label 上 —— `Text(...).foregroundStyle(.red)`。
   另外按用户要求,**去掉卡片底色**(不再是 `SettingsGroup`),只留按钮 + 一行说明文字。

## 复核方式(可复用)

截图后用像素量测,不靠肉眼:
- 用与背景亮度差 >0.02 找出**卡片**边界;用与卡片填充差 >0.035 找出**内容**边界;
  再沿行打印亮度跳变,直接读出控件右缘。
- 反复踩的坑:**取样点/量测窗口必须自适应**。窗口宽度、卡片高度一变,写死的坐标
  (比如 `cardRight = 1934`)就全错,还会把窗口外的像素当成内容 → 报出 "-64pt" 这种荒谬数字。
  另外量"内容左缘"时,SF Symbol 的字形比它的 18pt frame 内缩约 5pt,会误导成"左留白 17pt"。
- 卡片填充色:`.quaternary` 实测 0.921(明显偏灰),`.quinary` = 0.963,接近原 `GroupBox` 的 0.975,
  最终用 `.quinary`。
