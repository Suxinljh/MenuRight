## 现象与根因

- 真机截图(m02309):对话框 332pt 宽,密码框只有约一半宽(实测 `alertFieldWidth=126`),下面「把密码存进密码本」勾选框正常。
- 根因:`ArchivePasswordPrompter` 原先把 `NSSecureTextField` + `NSButton(checkboxWithTitle:)` 放进竖直
  `NSStackView(views:)`(`alignment = .leading`)。**stack view 按子视图的固有宽度排布**,而文本框的固有宽度就是占位符
  「输入密码」的宽度 —— 设了 300pt 的 frame 也没用,布局时被覆盖。所以这不是"frame 写错了",是**布局方式选错了**。

## 修法

- `MenuRight/App/Settings/ArchivePasswordPrompter.swift` 把 alert 构造抽成可测的纯函数:
  `static func makePrompt(text: (StringKey) -> String, archiveName: String, afterFailedAttempt: Bool) -> Prompt`,
  `struct Prompt { let alert: NSAlert; let field: NSSecureTextField; let remember: NSButton }`;
  `askForPassword(forArchiveAt:afterFailedAttempt:)` 只负责 `runModal` 与取答案。
- accessory 改成**纯 frame 布局**的 `NSView(frame: NSRect(x: 0, y: 0, width: 320, height: 58))`:
  - 密码框 `NSSecureTextField(frame: NSRect(x: 0, y: 34, width: 320, height: 24))` + `field.autoresizingMask = [.width]`
    (`NSAlert` 会按 accessory 内容定对话框宽度,`autoresizingMask` 保证父视图被拉宽时密码框跟着走);
  - 勾选框 `remember.frame = NSRect(x: 0, y: 4, width: remember.fittingSize.width, height: 22)`;
  - NSView 坐标原点在左下:密码框在上(y=34..58),勾选框在下(y=4..26),间距 8pt。
- **结论:别再用 `NSStackView` 装这个 accessory。** 已在源码里留注释说明原因。

## 顺手修的测试隔离(重要发现)

- 第一次跑全套时**整套测试挂死 10 分钟**(`xcodebuild` + `xctest` 一直活着),`sample` 抓到:
  `CustomCompressionDialogTests.testCloseTakesTheWindowAwayAndLeavesNoDialog → CustomCompressionDialogWindow.show →
   ArchivePasswordBook.shared → ArchivePasswordBook.init(storage:) → KeychainArchivePasswordBookStorage.load() →
   SecItemCopyMatching`,即**测试进程读真钥匙串里的密码本,被钥匙串授权弹窗卡住**(`SecurityAgent` 起来了,没人点)。
  同一条目 `/usr/bin/security find-generic-password -s xin.ljhsu.MenuRight.password-book -a compression` 也阻塞;
  而同一把钥匙串里新建/读/删一个探针条目都是秒回 ⇒ 钥匙串没坏,是**这个 item 的 ACL 需要用户点授权**。
- 修法(产品代码里留一个可测的缝):`CustomCompressionDialogWindow` 新增
  `var passwordBookProvider: () -> ArchivePasswordBook = { MainActor.assumeIsolated { ArchivePasswordBook.shared } }`,
  `show` 用 `.environmentObject(passwordBookProvider())`;测试在 `setUp` 里注入
  `ArchivePasswordBook(storage: InMemoryArchivePasswordBookStorage())`,`tearDown` 里还原。改了
  `MenuRightTests/CustomCompressionDialogTests.swift` 与 `MenuRightTests/FileOperationDispatcherTests.swift`
  (`customize` 路径会建真对话框的那个用例)。**单元测试从此不碰真钥匙串。**
- 教训:凡是"默认指向钥匙串的 `static let shared`"被测试路径间接引用,都可能把整套测试挂死;测试必须有注入缝。
